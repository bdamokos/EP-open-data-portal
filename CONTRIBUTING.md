# Contributing

Create a branch and open a pull request with the problem, resulting behaviour and validation. Keep unrelated changes separate. Include mobile and desktop screenshots for visible changes.

Run `npm ci` first; test runs without it are not validation evidence. Iterate with `npm run test:fast` or a focused file (`npm test -- server/example.test.mjs`). Before opening a PR, run the full suite when the environment allows:

```sh
npm ci
npm test
npm run check
npm run build
```

`npm test` discovers all `src/*.test.mjs`, `server/*.test.mjs` and `scripts/*.test.mjs`. `test:slow` runs the explicit subprocess manifest; `test:server` and `test:frontend` restrict directories; `--scripts` selects script tests. Combine them with profiles, e.g. `npm run test:fast -- --server`. Explicit file arguments override the profile. Runner flags such as `--test-reporter=tap` pass through to Node. `TEST_CONCURRENCY` overrides concurrency (local default: half the available CPUs, minimum two; CI: Node default); `TEST_TIMEOUT_MS` sets the default per-test timeout (120000 ms). Tests with explicit timeouts retain them. On Linux the runner gives tests a private temporary directory on `/dev/shm` when it has at least 1 GiB free, because SQLite and cache fixtures are fsync-heavy; `TEST_TMPDIR` selects another parent directory, and the directory is removed after the run. The runner also releases each `t.after` callback once it has run, because `node:test` otherwise keeps every finished harness (window, module runner, React root) until the file exits. Share Vite transform servers through `src/test-support/viteRunner.mjs` instead of calling `createServer` per test: each closed server stays in memory. Settle every deferred fetch fixture at teardown; an unsettled request keeps its client deadline timer, and with it the test process, alive for up to 40 seconds. On machines with 4 GB of RAM, `npm test -- --max-old-space-size=1024` bounds each test process's heap at some cost in speed. Outbound network is blocked, including in Node subprocesses through the inherited `NODE_OPTIONS` preload; use fixtures or mocked fetch.

Loopback tests report a reason when sandbox permissions deny listening; CI fails instead of skipping. `TEST_SIMULATE_NO_LOOPBACK=1` is a test-only way to verify that behaviour, including the CI failure. Report sandbox loopback/subprocess skips in PR validation and rely on CI for full coverage.

The Checks workflow runs these steps for pull requests, including drafts, and for pushes to main; it can also be started manually for any branch. It runs on GitHub-hosted standard runners at no cost to the public repository, so opening a draft pull request early is the cheapest way to run the full checks from a constrained machine. It uses read-only permissions and no deployment secrets. Maintainers should require its `test-and-build` check and review before merging. Repository visibility, branch protection and release permissions are managed separately.

Keep `.nvmrc` and the Dockerfile's Node version aligned. Pin `NODE_IMAGE` to the official multi-platform image index digest so build, dependency and runtime stages share an immutable base across supported architectures. The runtime-image check asserts the actual Node version, exercises valid and malformed Brotli decoding, and checks startup and built assets; run it for any image built with a `NODE_IMAGE` override as well.

For an API response contract change, update the affected endpoint `*_VERSION` and run:

```sh
npm run api:bump
node --test server/api-version.test.mjs scripts/api-version.test.mjs
git add server/api-version.mjs
```

The command fetches `origin/main`, keeps every recorded main revision/digest pair, renumbers branch-only entries after main's latest revision, and appends the current endpoint inventory digest if needed. Repeated runs are unchanged. It writes only `server/api-version.mjs`; review and commit that change with the contract change. It neither stages files nor changes branches, installs hooks, commits, or pushes. Fetch failures stop before writing. Do not bump for builds, releases or data refreshes.

`API_CONTRACT_REVISION` and registry keys increase without wrapping. `API_VERSION` runs from 1 to 999, then returns to 1: revision 1000 exposes version 1. Keep all earlier registry entries. Requests still use only `v`; reusing a number relies on existing caches expiring between cycles.

After merging or rebasing main (or another branch in a stack), resolve endpoint code first and rerun `npm run api:bump`. For conflicts in `server/api-version.mjs`, leave Git's ordinary or diff3 conflict markers in place: the tool preserves both sides' recorded digests and renumbers their entries after main. It refuses conflicts in helper code outside the version declarations; resolve those manually first. Then stage the result and continue the merge/rebase. Run it again when main advances before merge; do not edit or discard recorded digests to make a check pass. Branch entries whose original revision/digest pair already appears on main are treated as landed; equal digest values at different revisions are retained.

For a response-semantic change that does not change the endpoint inventory digest, use `npm run api:bump -- --force` once. This deliberately appends another revision with the same digest; ordinary reruns remain unchanged. The digest cannot detect semantic changes without a changed endpoint version, so reviewers must still check this case.

`npm run api:check` is read-only and compares the working registry with the locally available `origin/main`; fetch main first when using it locally. `-- --base <ref>` adds a stack parent baseline: its branch-only digests must survive after main, but may move to new revisions. `API_VERSION_BASE` supplies CI's immutable PR base or previous main commit. `API_VERSION_MAIN_BASE` pins the protected main history: the immutable base SHA for a PR targeting main, the previous commit for a push to main, or the fetched `origin/main` for a stacked PR. CI preserves main's exact mappings and each occurrence of a parent-only digest, and runs the normal digest test. Neither CI nor `npm test` performs an automatic bump, so unbumped endpoint changes still fail. No hook is required; if using a local hook, keep it read-only (for example `npm run api:check`) and stage bumps explicitly.

Style components with the design tokens in `src/theme.css`, never raw colour values. Each token has a light and a dark value, and every view uses the same surfaces in both schemes; the political-group, vote and status colours are reserved for data. Keep the interface independent of European Parliament branding. `src/theme.test.mjs` checks token contrast and rejects raw colours, and the focus tests run in both schemes. Check visible changes in light and dark appearance.

Use the shared roles in `src/Controls.css`: underlined tabs navigate between sections; segmented controls switch presentations of the same content; outlined buttons perform secondary actions; `.ui-primary-action` marks the main action explicitly. Controls use the shared height, type and corner tokens. Applied filters use the accent tint and a remove control. Question status labels use compact rounded pills; motion status labels use an icon and text without a border. Keep view-specific layout separate from these shared treatments.

Use `:focus-visible` for focus indicators, including headings and readers that receive programmatic focus. Keep the shared styles in `src/focus.css`: controls use a ring and editable fields use a border highlight, with a transparent outline for forced-colour modes. Search fields strengthen their existing underline. Preserve autofocus, focus restoration and dialog focus management.

Write interface text for readers: plain, brief and free of disclaimers, hedges and robotic phrasing. Before adding a sentence, ask whether a reader would miss it. Coding agents tend to add caveats and explanations to UI copy; report uncertainty, gaps and limits to the maintainer in full in the PR description, review replies or chat instead.

- The site notice (`src/components/DataNotice.tsx`) states once that the site is independent, that its counts may be incomplete or out of date, and that readers should check the original. Do not repeat that inline.
- Link only to human-readable public pages; `sourcePageUrl` and `SourceLink` in `src/SourceLink.tsx` apply this rule. Never link to or display machine endpoints (API, JSON-LD, SPARQL, concept URIs, the developer corner), request URLs, retrieval timestamps or record IDs as evidence. Without a public page, show no link and no note about it.
- Use "Partial" only for a concrete missing record, failed read or bounded omission affecting the displayed selection. A recent event date, unknown future publication or an unrelated archive failure is not a gap. Name the missing item or affected dates briefly; include its exact human-readable Parliament page when known. Omit generic coverage disclaimers. Keep unknown values distinct from zero.
- A debate's child URI alone does not identify a speech: declarations can include procedural markers such as the catch-the-eye section. Qualify a member's speech count only when typed, attributed evidence identifies a missing contribution by that member. Keep unclassified references in diagnostic metadata and let the API recovery worker classify them.
- Do not state what the app does not infer or claim, and do not explain methods. Add one line only where it changes how a number reads, such as "Shared questions count once per country".
- Keep pipeline and maintainer terms out of public views: index generations, parsers, source variants, load states, what an API returned.
- State empty and error states in a few words ("No matching amendments.", "Transcript unavailable."), without reasons or advice. Omit helper captions, such as search-scope notes, unless the reader can act on them.

UI messages use stable IDs in `src/ui-locales/en.json`. React components read the scoped formatter with `useUiI18n`; presentation helpers accept a formatter explicitly. Use whole messages and named rich slots. Keep source wording, identifiers and source-language tags in those slots; never look up arbitrary API strings or rewrite rendered DOM text. Text-only elements such as SVG titles use `ui.t` directly. `UiMessage` accepts separate numeric `counts` when a displayed count is a rich node.

Language assets are flat `src/ui-locales/<language>.json` dictionaries keyed by canonical message ID. `existing.json` retains the exact earlier translations, and `aliases.json` maps earlier extraction keys to canonical IDs. Missing messages fall back individually to English. Do not create English copies for untranslated locales. The interface code `pt` dispatches with `pt-PT` rules.

`plural-pairs.json` declares each source plural family and its count parameter. Reviewed native forms belong in `plural-forms.json` as language → primary message ID → category → template; forms merge with the translated family before placeholder validation. Use `Intl.PluralRules` categories through the formatter, including independent selectors in messages with several counts. Owned errors carry IDs and parameters through `UiMessageError`; render them with `uiErrorText`. Preserve external API error messages literally.

Use public sources and retain exact identifiers, dates, languages and attribution. Document a new source in `docs/PUBLIC_DATA.md` and add bounded, attributable test examples. Keep unavailable observations distinct from zeroes.

Do not commit credentials, private datasets, browser storage, generated caches, runtime databases, host addresses or site-specific deployment configuration. CI does not access a deployed website or run an indexer. Deployment is separate from pull-request checks.

## Amendment benchmark

After `npm ci`, set `AMENDMENT_BENCHMARK_API_BASE` to the public explorer's HTTPS origin (or pass `--api-base HTTPS_ORIGIN`), then acquire a frozen snapshot with `npm run bench:amendments -- --fetch --request-cap 2500`. No deployment origin is built in. Acquisition is sequential, at least 750 ms apart; attempts and approved official DOCX redirect hops count against the cap. HTTP 429/503 `Retry-After` is honoured up to 60 seconds; a longer delay aborts rather than retrying early. `--retry-after-cap-ms` can lower that ceiling. Network errors and 5xx responses are never cached. Missing inputs, exhausted request caps and malformed catalogue/context responses abort acquisition, without producing a score.

The default sample is term-10 amendments with indexed plenary decisions in the latest eight Monday weeks containing decisions, through the snapshot's Brussels date. `--weeks N`, repeatable Monday `--decision-week YYYY-MM-DD`, inclusive `--from YYYY-MM-DD --to YYYY-MM-DD`, or repeatable exact `--document`/`--report` IDs select other samples. `--exclude-snapshot /path/to/other/snapshot.json` (repeatable) excludes every exact amendment ID in that snapshot’s frozen sample, including unresolved rows and amendments decided in several weeks. Exclusion snapshot IDs and the excluded ID union are sealed into the new sample; pass the same selectors when replaying. One variant per amendment is evaluated by English, language code, then list ID; alternatives remain recorded. Provisional-agreement decisions are not placeable amendments: their rows remain in raw counts but are excluded from the headline and vote denominators. A collective/split decision counts once and requires all sampled linked placeable amendments to be correct.

Inputs and JSON/Markdown results stay outside Git in `${XDG_CACHE_HOME:-~/.cache}/ep-explorer/amendment-benchmark`; override with `AMENDMENT_BENCHMARK_CACHE_DIR` or `--cache-dir`, and optionally `--output-dir`. Use a new cache directory for every snapshot. Acquisition freezes the catalogue, indexed amendment DOCX lists, exact EP report/motion metadata and selected DOCX files, and Commission proposal candidate/RDF metadata and discovered act/annex DOCX parts. Selection uses the public source readers and exact report/proposal identities, independently of amendment extraction. Live text/proposal projections are retained only for comparison. Exact source file declarations in the frozen public document catalogue can supplement a missing language in current EP metadata; both observations remain recorded. `snapshot.json` seals the sample and full URL, negotiated representation, hash and retrieval manifest. `--acquire-only` seals inputs without scoring; rerun without `--fetch` offline. Keep the checkout fixed throughout evaluation.

For language-selection changes, `--language-variants` supplements a separate snapshot with exact public target/list metadata and one matching-language DOCX list and document per selected list. Selection uses declared languages and exact list/number identity, independently of extraction success. These document bytes are re-extracted locally. Use a new cache or copy the inputs into a new cache before acquiring supplements; never modify a sealed snapshot. Compare full per-amendment outcomes on the same supplemented inputs when source producers change.

`--source-selection /path/to/selection.json --request-cap 0` tests retained English sources missing from a sealed catalogue's wording variants, without acquisition. The external schema-1 configuration names `baseSnapshotId`, a `supplement` with its captured-input `directory` and `manifest`, and `bindings`. Each binding supplies exact `id`, `documentId`, `number`, `listId`, `language`, `kind` (`declared-list` or `report-list`), the captured `parent` URL/request/hash/retrieval time, and `source` URL/declared URL/hash. Selection requires the parent's typed list and forward relationship, published range and unique English declaration. Fileless report lists additionally require the native report cover and complete main amendment range. Captured Redmap URLs remain distinct from distribution declarations; no missing redirect or list response is fabricated. The mode records derived variants, original catalogue hashes and absent comparison projections separately, retaining all original HTTP responses, null languages and404 observations. It cannot override indexed wording. Source-selection results have their own input/selector identity; compare clean main and candidate on identical selections and captured inputs. Review and accept the protocol before recording a separate baseline, and distinguish newly measured existing recall from runtime improvements. Acquisition, language, diagnostic and placement-only flags cannot be combined with this mode.

Evaluation re-extracts wording, calls the checkout's proposal source/identity reader and parser, extracts document text and selects resolution bodies with checkout code, then invokes the shared document-context placement function. No live text or proposal projection supplies evaluated placement inputs. Results retain live versions and a separate live-projection score to show the effect of source replay. Missing cached inputs abort, including requests introduced by changed identity/source selection; use a new snapshot to acquire additional inputs. A sealed406 that explicitly advertises the allowlisted CELLAR DOCX compatibility type retains an explicit `missing-declared-representation` acquisition gap only when that exact item URL/Accept/language observation is absent from the manifest. Its original406 request, response hash and provenance remain recorded. Every unrelated missing observation still aborts. New negotiated bytes belong in a separate sealed source extension that preserves all original observations; measure clean main and candidate on identical extension inputs and the same harness. Count any gains only on that extension. Parser limits never prove source absence. Resolution assertions derive boundaries independently from source rows and formatting; uncertain extents stay unverified. The non-holdout identity oracle also checks explicit English Na/new Naa/Nb interior quoted insertions in retained Word ZIP/XML. It requires exact raw amendment fields and complete comparison columns, one named-act outer instruction, the full predecessor continuation and a real following sibling inside the complete quotation. Projection paths and text supply coordinates only after native correspondence checks. Terminal, ambiguous, cross-language and other nested families remain unverified. The fixed hold-out and canonical language oracle retain their existing coverage. Unique reason counts are disjoint; pattern taxonomy rows overlap.

Source replay advances cache age to the latest source response time encountered. Each record retains its captured retrieval time, including when an immutable observation is replayed by a refresh. An admitted offline refresh finishes before the next source read, while the triggering read retains its stale label. This replay schedule does not measure live refresh latency. Compare harness changes separately on the same clean runtime before adopting a new measurement protocol; preserve historical reports and raw oracle expectations.

A resolved English CNS report reference retains `consultation-source-not-in-snapshot` when its exact Commission discovery request is absent from a sealed manifest, as with unsupported Council and existing-law discovery. It supplies no baseline or placement. Present discovery records continue through the normal source reader; missing downstream records still abort. Additional CNS observations belong in a separately sealed extension retaining every original input, measured on the same main/candidate sample and harness.

Replay the same snapshot/sample with `npm run bench:amendments -- --baseline /absolute/path/to/baseline.json`. The full-outcome gate requires an identical sealed sample/manifest, reports metric and taxonomy deltas and every regressed amendment, and fails on any false placement, missing row or deterioration from `correct`. Producer changes and live/checkout version differences no longer refuse cached-source comparisons. `--placement-only` remains a compatibility alias for this full gate. Older projection-only snapshots require a new acquisition. `--runtime-root CLEAN_CHECKOUT` measures another checkout's producers and placement through the same harness and oracle; the result records both identities.

For each snapshot, keep an append-only `ratchet.md` and `baseline-current.json` in its output directory. Begin with a clean main baseline. During migration, a baseline drawn from its recorded live-projection comparison must be labelled `live-projection-comparison`; its delta includes enabling source replay. After merges, the next stream or orchestrator measures the new main on that same snapshot, appends its revision, result file, correct/eligible counts, headline and false placements, and advances `baseline-current.json`. Never replace prior rows or baseline files. PRs may not regress any previously correct amendment and must have zero false placements. Keep snapshots, results and verification evidence outside Git and public CI artifacts.

The hold-out is **measure only, never tune on these rows**. Select and freeze disjoint earlier decision weeks before measuring outcomes; keep its own ledger and baseline. Amendment PRs report both the main and hold-out snapshots against their current baselines. Improving the main sample fails the ratchet if any previously correct hold-out amendment is lost or any false placement appears. Hold-out findings are reported with official-document evidence; do not use these rows to choose or refine placement rules.

### Language parity

`--languages` evaluates every sampled list/number in all 24 languages, including missing editions and extraction failures. The fixed sample covers legislative and non-legislative reports, discharge reports, B/RC motions and second reading. It uses anonymous public metadata, declared distributions and Commission source files; every replay rebuilds wording and projections in-process. Python 3 is required for the independent ZIP/XML reader.

Use a new directory for acquisition, then record the first ratchet row from a clean checkout of current `origin/main`:

```sh
npm run bench:amendments -- --languages --fetch --acquire-only --cache-dir /absolute/path/languages-YYYYMMDD
npm run bench:amendments -- --languages --cache-dir /absolute/path/languages-YYYYMMDD --runtime-root /absolute/path/clean-main --record-language-baseline
npm run bench:amendments -- --languages --cache-dir /absolute/path/languages-YYYYMMDD
```

The last command automatically compares with the latest row in that snapshot's append-only `ratchet.jsonl`; `--baseline PATH.json` selects an explicit report. Any loss of a previously correct language observation, missing row or false placement fails. `--record-language-baseline` appends a clean measured revision only after comparison passes. An oracle implementation change retains a baseline only when every raw expectation and verification assertion is identical; scoring changes require reviewed calibration. Keep this ledger separate from the identity benchmark and use the same sealed snapshot throughout a comparison.

Reports give planned and published denominators, correct legal placements, explicit `not-applicable` observations, placed-unverified, withheld reasons and false placements for each language. No-change observations remain in the totals and receive no legal-placement credit. Parity pairs use the exact list ID and amendment number; outcome parity and independently verified semantic locations are counted separately. Insertion parity compares the existing predecessor boundary across published suffix/alphabet conventions; JSON separates withholding from weaker oracle coverage behind English. Shared withholding counts as outcome parity. Raw published comparison cells establish expected operations; literal source headings and XML paths establish supported section, recital and sibling-boundary checks independently of production labels and proposal trees. The independent scope oracle matches complete, source-attested cells in their recorded language; partial notes remain wording and unattested languages remain unsupported. Complex quoted provisions, automatic numbering and unsupported boundaries remain unverified. These scores cover the sample, not all multilingual publications. Keep sources, reports and manual verification evidence outside Git and CI artifacts.

Correcting false ground truth requires an explicit migration decision. Preserve historical reports and ledgers, enumerate each changed observation with original/corrected classifications and source hashes/paths, and replay clean current main and the candidate using the same corrected oracle and frozen inputs. Report legal placement gains separately from no-change outcomes and audit every other previously placed row. A calibration does not waive the ratchet: losses of recorded `correct` rows still fail until the maintainer accepts the scoped migration.

Canonical cached-source replay can verify a numeric citation marker against its native Word dash marker only after the ordinary original-span assertion fails. The source-bound check requires exact sealed English motion/amendment observations, complete comparison columns, an uninterrupted native preamble, and matching source paths and coordinates. It preserves words, numbers, case and all other punctuation; only the owned leading markers and whitespace may differ. The row retains the previous assertion and exact source binding in `nativeCitationEvidence`, under protocol `native-citation-marker-v1`. Incomplete proof leaves the original result unchanged. This check cannot acquire sources or repair other failures; the fixed hold-out and language oracle remain unchanged. `scripts/amendment-benchmark-citation-harness.mjs` remains available for explicitly labelled experimental before/after probes. Scoring changes still require the reviewed migration above and append-only ledger recording.

`npm run bench:council-languages -- --snapshot /absolute/path/snapshot.json --runtime-root /absolute/path/clean-checkout --output-dir /absolute/path/results --request-cap 0` measures a separate controlled Council cohort: A-10-2026-0175 amendments 1–8 in EN, FR, HU, PL and GA. Supply an external sealed wrapper referencing the retained research manifest, original observation hashes, native Word/XHTML/RDF inputs and independent expected assertions. The command supports no acquisition or source fallback; missing captures abort. It exercises the runtime Council provider and shared wording/placement functions. Python 3 independently verifies native source hierarchy, complete comparison cells and insertion boundaries. Typed-note scope remains unsupported, Irish spelling conflicts remain distinct, and French apostrophe mappings retain both originals. Whole-document projection gaps remain visible.

Use the same wrapper and harness with `--baseline REPORT.json` for clean-main/candidate comparisons. Reports separate legal-correct, placed-unverified, withheld, unsupported native assertions and false placements, with eight distinct amendments and forty edition observations. New unsupported placements fail the gate; no-change has no placement credit. All previously placed boundaries, operations and source identities are protected. This additive measurement never writes a baseline ledger or replaces any of the six existing gates. Keep inputs, expectations and results outside Git and CI artifacts.

## Plenary agenda benchmark

After `npm ci`, capture anonymous raw Open Data inputs once into a new directory outside Git:

```sh
npm run bench:agenda -- --fetch --api-base HTTPS_ORIGIN --cache-dir /tmp/agenda-inputs --week latest
```

Acquisition reads current-term `/meetings` catalogues (50 rows/page, at most ten pages/year), then at most two agenda pages for each of the selected week's one to five sittings. The supplied public app origin (`--api-base` or `AGENDA_BENCHMARK_API_BASE`) supplies one anonymous `/api/activity-index/status` observation. Its exact response bytes, URL, retrieval date and hash are kept in `index-status.json`; there is no built-in deployment origin. An existing observation can be supplied with `--index-status PATH.json`. Use `--week YYYY-MM-DD` (Monday), `--sitting MTG-PL-YYYY-MM-DD`, or `--lang hu` when capturing a different sample. The default is the UI's English latest-week request. Every parliamentary input keeps its exact URL, HTTP status, retrieval date, byte hash and observed header/body latency. Requests are sequential, at least 750 ms apart, with an 80-request cap including the app-status read (`--request-cap`, maximum 200), 12 MiB/Parliament response and 64 MiB total limits; app status is capped at 1 MiB. Redirects, transient errors and incomplete catalogue acquisition abort. HTTP 429/503 stop immediately; acquire a new snapshot after the source's pause. A later-page catalogue 204 is retained as a terminal observation, not a successful empty first page. Agenda 204/404 observations remain gaps under the existing reader's rules.

Rerun the same snapshot offline, using `--baseline` for subsequent changes:

```sh
npm run bench:agenda -- --cache-dir /tmp/agenda-inputs --latency zero
npm run bench:agenda -- --cache-dir /tmp/agenda-inputs --latency recorded --baseline /absolute/path/to/baseline.json
```

Each run defaults to five iterations of four states: empty source/view caches in a fresh process; a warm repeat in that process; fresh retained source records with no assembled view in another process; and a restart with the first process's assembled view. Replay uses the checkout's actual ODP admission queue, disk/memory source caches, calendar/legislation services and view cache. A missing replay URL aborts; it never goes online or becomes a source gap. Successful source records are seeded as fresh; negative observations retain the application's normal cache behaviour. All services use the snapshot's fixed selection clock. Temporary replay caches/indexes are removed after measurement.

`recorded` replays the capture's header/body waits without network; `zero` removes those waits to expose local work. JSON/Markdown reports go to a sibling `-results` directory (or `--output-dir`). Elapsed time covers the service query and response serialization. Reports include median/p95 and individual runs, process/import/readiness-loading times, CPU, heap/RSS, event-loop delay, inclusive parent/child spans, exact source calls/bytes and full coverage. Nested spans overlap; do not add their durations. Five samples are a baseline, not a tail-latency estimate.

The agenda list receives the real app's frozen readiness/coverage response. Its member count, serving generation, partial coverage and source dates remain observed values. No index database or member/source rows are generated. This measures agenda service assembly, excluding index database queries/collection, OS-cache eviction, background load, HTTP/CDN, directory bootstrap, browser assets and rendering. Recorded latency is one source observation, not live-site acceptance. Add a browser/navigation measurement separately if these service timings do not account for the reported delay.

Comparison requires identical snapshots, protocol/iterations, runtime/hardware and instrumentation. Full ordered responses must match after removing only `fetchedAt` and `computedAt`; exact IDs, wording, languages, coverage, errors and freshness flags remain. Response differences, failed/incomplete runs and increased transport counts fail the gate. A median slowdown fails only when it exceeds both 10% and 20 ms; change the margins with `--max-regression-percent` and `--max-regression-ms`. Hold the checkout fixed while measuring; reports record its revision, dirty diff, source-tree and harness hashes. Keep raw inputs, reports and experiments outside Git and public CI artifacts.

Add `--session-cases` to probe stale cache behaviour using the same real input bytes and statuses. A historical snapshot gets an aged-view probe (seven hours) and a next-day probe (24 hours). A snapshot containing a sitting on its actual Brussels observation day gets a 16-minute current-sitting probe instead, only if that advance stays within the same Brussels day; future sittings are labelled separately. Reports separate calendar and agenda recheck starts, including an explicit gap when the current agenda was not rechecked at the probe's age. Source chronology is never rewritten to manufacture current-session coverage. Missing current-session, changed-observation and failed-recheck coverage remains explicit.

These probes prime the real caches, advance their clocks, and hold replay responses until cached data returns or a 250 ms guard releases a blocking read. Their timings include the guard when blocked. They record response latency, starts before return, recheck work and later verification reads separately. The entire ordered topic payload must remain unchanged through response and refresh; base/head topic and response hashes are also checked. No title change or HTTP failure is injected. Historical policy targets are no routine recheck and no upstream-blocked cached load; existing gaps remain explicit rather than being mistaken for an optimised baseline. `--runtime-root CHECKOUT` runs another checkout through the same instrumentation and frozen observations.

The full amendment corpus remains an offline benchmark. Use the complete sealed public snapshot and existing regression gates, keeping every unavailable or unverified case in its documented category. Do not replace it with a small generated CI sample or upload its cache/results to GitHub. CI continues to run the normal test, type-check and build suite; publish concise results from real offline runs in the PR comment, including exact revision, snapshot, coverage and comparison limits.
