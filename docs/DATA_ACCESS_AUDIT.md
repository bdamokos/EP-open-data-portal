# Data access audit

## Outside voices, 16 October 2026

- Uses the existing anonymous Open Data API v2 fetcher, upstream queue, 12 MiB response bound, request budget, writer lease and persistent task cursors. No authenticated service, private export, production cache copy or second source/index writer was added.
- Retains compact oral-speech metadata, exact person/agenda/procedure identifiers, original speaker headers and XML language tags, dated MEP roster IDs, source URLs and retrieval timestamps. Term-9 member speech metadata is removed after roster classification. Speech bodies are read only on demand through the existing reader.
- The same generation stores `outside_contributions` and the supporting source observations. An older accepted generation stays readable during refresh. A first upgrade can serve the new partial speaker generation while existing activity views retain their accepted generation. Existing speech cursors and core missing-graph-node retries remain intact. Optional outside context failures become recorded gaps after three attempts and retry next generation.
- `/api/poc/outside/directory` and `/api/poc/outside/{person-id}` only read the index. Terms are 9, 10 or all. The directory, speaker page and day panel request only term 10; earlier-term UI links cannot broaden that selection. Classification rules are reapplied to retained role text on read without changing the saved source observations. Directory filters remain scoped in the URL. A 50,000-row selection limit, source gaps, missing identities and missing parent links keep coverage partial. No invitation register or committee-wide person resolution is claimed.
- Header identity requires the exact API participant reference. Capacity groups are derived from source role text, not names or today's job title; original source conflicts remain visible. Subjects follow exact agenda links and verified procedure types. Public-source fixture tests cover a former-MEP false positive, the original-English Szłapka conflict, mixed-language XML, special events, cross-term guests and legacy transcript URLs. Browser validation uses an isolated subset of saved public observations, never the production index.

The standalone application has no credential-dependent parliamentary data adapter. All external information reads use the public sources listed in [Public data sources](PUBLIC_DATA.md).

The extraction excludes authenticated CODICT SOAP access, CMS database exports and their fallback rosters/profiles/news, NewsHub integration, local exhibition media, and the UDP display bridge. Their configuration, credentials, export scripts, routes, assets and dependencies are absent. The frontend has one application entry and no link to another application.

The API exposes read-only explorer routes. Requests cannot select an arbitrary upstream host. The adapter constructs fixed official endpoints and validates document, recording, portrait and source identities. Outgoing requests set content negotiation and a user agent; they do not forward the caller’s cookies or authorization. Configuration contains local server, cache and index settings, without external service credentials.

The DOCX extraction check on 16 October 2026 used the public B-10-2026-0431 distributions in English, French and Hungarian. Translation tags and brace values belong to hidden character styles in the same DOCX archive. Extraction now reads those styles locally and respects inherited hidden text without stripping visible angle brackets or braces. Existing extracted text is replaced on its next request; a failed upgrade reports unavailable text and preserves the old disk record. No additional source, authentication, production cache copy, corpus download or writer is introduced.

Portrait requests check a bounded local binary cache before resolving the member profile, so a fresh disk hit makes no parliamentary API or website request, including after a restart. Only validated official JPEG paths may be downloaded; redirects, non-JPEG responses, empty bodies and bodies exceeding 2 MiB are rejected. Cache records preserve source identity and retrieval time, validate integrity on read, and are written atomically within a 128 MiB / 2,048-record budget. A refresh failure preserves the previous record. No new external source, credential, proxy route or production cache is introduced; the optional `ODP_CACHE_DIR/portraits-v1` directory uses the existing writable cache mount. See [Public data sources](PUBLIC_DATA.md) for expiry, stale-image and retry behaviour.

Anonymous checks on 15 October 2026 returned public content from the MEP API, OEIL procedure and first-reading summary pages, Publications Office SPARQL, Multimedia Centre recording metadata and the published player code. The public player’s metadata connection returned a matching `PUBLISHED` recording and its language map without authentication. These checks establish access to the sampled records; they do not promise permanent endpoint availability or complete archives. The machine-readable dated observations are in `public-source-checks.json`.

The current-term date-range check on 15 October 2026 used the same anonymous Open Data API, with a one-record response limit. It confirmed that a July 2024–October 2026 speech request succeeds; the removed 365-day limit belonged to this application's controls and shared query validator. The exact request and sampled identifier are in `date-range-check.json`. Wider question and procedure windows read the existing index; MEP speech clouds retain their selected-view pagination and coverage budgets. No source, authentication method, cache writer or index writer was added.

Timeline titles and milestone badges reuse anonymous `/procedures/{id}` data and the existing index writer. Older projections are refreshed once to retain `process_title`; an explicit null preserves a genuinely missing title without repeated upgrade requests. Milestones retain exact activity types and dates, source links and retrieval dates. Missing milestones do not imply non-adoption; scheduled future dates are excluded. No new source, authentication, production cache copy or writer is introduced.

Motion-outcome enrichment uses the same anonymous Open Data API and existing activity-index writer. It adds bounded sitting-level vote-result/decision tasks, including non-roll-call methods, and retains only relationships, English document references, explicit outcomes and optional totals. It does not import named-voter lists, infer a result from vote totals, join by similar titles, or send source requests while serving activity pages. Exact declared child IDs detect incomplete responses, including endpoints that ignore the requested page limit. Existing generations, source files and durable cursors are preserved during projection upgrades. Public examples checked on 15 October 2026 cover an adopted joint motion, a lapsed original and an adopted show-of-hands motion; no institutional authentication or production cache was used.

The motion example also includes two document details checked anonymously on 16 October 2026 to verify the shorter final-motion label: rejected B10-0465/2026 and adopted RC-B10-0438/2026. Incomplete vote refreshes preserve previously complete sitting records and their source dates, with failed-attempt provenance retained separately. The derived original-to-joint index contains only exact public document relationships; source-table triggers and the existing writer lease maintain it without an additional process or external data source. Related joint-motion authorship is checked from that text's saved exact author/person records, independently of the original motion; viewing the relationship starts no source requests.

Motion wording comparisons add anonymous, on-demand reads of the selected motion documents, their exact procedure links and `/adopted-texts/{id}` records, followed by the API-linked DOCX distributions. They reuse the existing bounded request queue and text cache, with no catalogue crawl, additional index writer, authenticated service or production-cache import. Both source texts must share a language and explicit public document relationships. Candidate, document, decompression and diff-size bounds leave explicit gaps when exceeded. Automatic numbering and referenced footnotes/endnotes are extracted locally; published decimal punctuation is preserved without interpreting a style difference as a numerical or policy change.

The plenary-history follow-up on 15 October 2026 checked anonymous `/meetings?year=2024,2025,2026&limit=50&offset=0` and offsets 50, 100 and 150, using the same official API and JSON-LD format. The official specification permits multiple years and offset pagination. The previous current-year, two-page and 16-sitting restrictions were application limits. Selectors now retain the full current-term catalogue, while agenda, speech and participation details remain selected-view requests with their existing coverage labels. Selected checks of the 16 and 17 July and 16 September 2024 agenda endpoints returned HTTP 204 (no content), while 20 January 2025 returned JSON-LD. Missing historical agendas remain explicit and do not hide the sitting catalogue. Weekly defaults reuse these anonymous, selected-view requests: agendas read only the published sitting days in the selected week, and speech clouds skip future days. Each item keeps its exact sitting identity and source provenance. No corpus download or additional writer is introduced.

Reference cards use the existing anonymous SPARQL endpoint, Open Data API and OEIL pages through the shared validated source client and cache owner. Keys are validated against fixed patterns before any query is built, so callers supply neither query text nor host. EUR-Lex and footnote link targets are only outbound links; the adapter never fetches them. The 15 October 2026 checks are in `public-source-checks.json`.

The optional full-text corpus uses the same anonymous Open Data API speech endpoint and the official DOCX distributions already linked from index records, through the existing allowlisted downloader. It adds no source, credential or proxy route. It has its own leased writer and opens the activity index read-only. See [Full-text corpus](PUBLIC_DATA.md#full-text-corpus).

Contextual search and exact stored-text reading query that corpus through a bounded read-only connection. POST search carries exact source-ID scopes in a size-limited JSON body; it performs no write or collection request. Question/answer grouping follows saved parent identifiers, and saved titles, authors and current-country labels use exact index joins. No dossier-document ingestion, institutional service, production-cache copy or additional writer is introduced.

Most interface labels are app-owned; the small bundled terminology catalogue adds exact Publications Office procedure-phase/EuroVoc labels retrieved anonymously on 16 October 2026, with Parliament-owned IATE corroboration. It retains public concept/query URLs, languages and retrieval dates. Simple interface phrases use separately identified machine translations. This adds no runtime fetch, authenticated service, cache/index writer or source-text translation. Country and language display names use the browser’s internationalization data. Portrait and favicon fallbacks are app-owned SVGs. The application uses system fonts and carries no inherited institutional font binaries.

Chair-only exclusions in the agenda contributor list reuse transcript headers from the existing bounded speech cloud and reader requests. The classification is scoped to exact speech/person IDs and does not infer participation from a person's office or speech length. The dated public header examples omit body text. No new source, request fan-out, authentication, cache writer or index writer is introduced.

Speech intervention classification, exchange reconstruction and MEP speaking statistics use the existing anonymous Open Data API `/speeches`, `/speeches/{id}` and `/events/{id}` routes. They read supplied XML headers, public procedure markers and exact JSON identifiers. They introduce no authenticated source, website scraper, credentials, production cache copy, database writer or background worker. Viewing a debate reads a bounded selected sitting through the same source cache and queue; member statistics paginate only the chosen MEP. The read-only `speech-context/{id}` and `speech-statistics/{member}` routes validate identifiers and query parameters. App-owned SVG icons carry text labels. Derivation rules, request budgets and count definitions are documented in [Public data sources](PUBLIC_DATA.md#speech-interventions-and-exchanges).

Procedural-note and chair-change parsing uses those same public XML records. Chair identities require exact participation IDs; generated individual speech links are suppressed for procedural records. Hiding trailing notes changes only the displayed chain, preserving source membership and coverage.

Reader deadlines and cancellation use request-local signals and retain independently owned shared source jobs. They add no external source or persistent worker. Timeout diagnostics contain public route paths and aggregate queue/timing figures, excluding query strings and request credentials.

No production cache or database was copied into the initial repository. Git history starts with the standalone source. Hosting access controls and private Git authentication are separate from parliamentary data acquisition and remain outside source control.

`npm test` checks the read-only routing boundary, allowed configuration and absence of authenticated data adapters. Future sources must document their public acquisition path here before being added. Failed public access must remain a reported gap; it must not trigger use of internal credentials or protection bypasses.

Activity grouping and Following answer updates read the existing saved public question/answer relationships. No external source, upstream request, index migration, or additional writer is introduced. Browser follows remain local to the device.

Plenary amendment trails add anonymous, bounded reads of existing report/motion details, `/documents/{doc-id}` verification of their exact URI-only or incomplete amendment-list links, and their explicitly linked DOCX lists, dated public MEP rosters (with bounded term-roster and individual mandate-profile fallback after source failure), sitting vote results/decisions and API-linked roll-call XML distributions. List details must verify the exact published document URI, amendment-list type and forward target; unresolved links remain incomplete and count toward the existing per-target bound. They reuse the activity-index writer lease, request budget and request queue; a separate additive job table is ignored by older workers and does not alter ordinary publication cursors. No authenticated source, private export, production-cache copy, additional writer or request-time download is introduced. Official voting aliases use `PersId` and retain their sitting date independently of dated mandate evidence. Derived author links and local amendment keys are labelled; decisions join only on exact EP amendment/component URIs. Literal split-parser failures persist outside generation pruning, can be inspected through a read-only endpoint and are retried when the parser version changes. Parsed selectors do not establish validated text spans or final adopted wording. Bounds and incomplete-refresh retention are documented in [Public data sources](PUBLIC_DATA.md#plenary-amendments).

The source reader added on 16 October 2026 reuses the anonymous Open Data API adapter and its existing cache/queue. It restricts hosts, endpoint families and filters, caps collection reads/downloads at 25 records and responses at 1 MiB, and preserves the original URL, filters, offset and retrieval date. Official website counterparts are outbound links only; DOCEO HTML is not scraped. The per-family mappings and explicit gaps are documented in [Public data sources](PUBLIC_DATA.md#source-links-and-record-reader). No credentials, institutional services, additional source/index writer or corpus acquisition are added.
