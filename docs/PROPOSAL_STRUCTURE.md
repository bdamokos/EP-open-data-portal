# Proposal structure

`server/proposal-structure.mjs` parses one exact Commission proposal content item. Acquisition and baseline identity checks belong to the source layer; the parser does not fetch documents, select translations, or apply amendments.

```js
import {
  parseProposal, parseTargetLabel, proposalCandidates,
  unitLabel, normaliseForMatching,
} from '../server/proposal-structure.mjs';

const proposal = parseProposal(docxBuffer, {
  language: 'en', item: 'act', sourceUrl: officialItemUrl,
  identity: { work: workUri, expression: expressionUri, item: itemUri },
});
const target = parseTargetLabel('Article 1 – paragraph 1 – point 4 – point a', 'en');
const candidates = proposalCandidates(proposal, target);
```

`parseProposal` also accepts a string or a document projection with `paragraphs: string[]`, optional `paragraphSources`, `paragraphProperties`, `paragraphFormats`, `documentObjects`, `tables`, notes and links. Plain text cannot establish original object or table completeness and produces `source-structure-unavailable`. Excerpts should supply `coverage: {complete: false}`. Use the DOCX buffer for complete extraction.

`server/public-legal-xhtml.mjs` adapts Publications Office OJ XHTML to the same unit contract for Council positions. Its separate `xhtml-` parser version and `sourceKind: 'xhtml'` retain the actual format. Explicit ELI subdivision IDs establish chapters, sections, articles, paragraphs, recitals and annexes; two-cell label layouts and inline enumerations establish list points without fabricating Word styles. Published `(a)`, `a)` and `i.` label cells retain their literal prefixes and nested list ownership. Quoted list scopes stay below their owning instruction. Notes and links retain displayed-text offsets. Unsupported grids and objects make only their affected passages incomplete. The standard static XHTML DTD declaration is discarded without loading it; entity declarations are rejected. The adapter never selects source identity or legal versions.

`server/formex-package.mjs` provides a separate, offline native Formex contract through `readFormexPackage(bytes, {source, coverage})`. `source` supplies the exact Cellar work, expression, manifestation, item, URL, CELEX, language and retrieval time; these caller bindings remain distinct from the parsed native metadata. The reader hashes the supplied archive and every entry. One `DOC` manifest establishes ordered main/annex parts; positioned `FORMEX.DOC` inclusions link recursively to separate parts. `manifest`, `entries`, `edges` and each part's mixed-content `tree` retain the package graph, attributes, native identifiers and XML paths. Metadata declarations and positioned inclusions remain separate edges.

Formex `containers` retain native parent/child order, exact labels and half-open block extents. `blocks` contain directly owned inline runs, UTF-16 marks, quotation characters and reference events, note anchors, links and positioned objects. `QUOT.S` remains a native quotation container; `QUOT.START`/`QUOT.END` keep their codes and reciprocal IDs. Notes retain their own blocks and numbering attributes; unverified display labels remain null. Page and consolidation processing instructions remain inert, positioned metadata. Consolidation changes add local gaps: deleted native wording is retained, and the reader does not compute the applicable text from those markers. Formulas, TIFFs and unknown content retain U+FFFC and local gaps. Included documents retain a positioned link and their own hierarchy; they are never flattened into the enclosing legal address.

The Formex reader accepts at most 256 entries, 8 MiB compressed, 8 MiB per inflated entry and 24 MiB inflated in total, with separate XML, block and recursion limits. It rejects traversal, duplicate/overlapping entries, bad CRCs, encryption, external entities and DTDs, and never expands files to disk or loads schemas. `packageComplete` describes the declared graph; `complete` also requires supported content. Excerpts use `coverage: {complete: false}` and retain the original observation hash separately from the supplied excerpt archive hash. Cross-format fidelity and legal projection remain unverified even for complete native extraction. Formex preference stays held: this reader is not wired to source selection, rendering or placement, and the XHTML path remains unchanged.

`server/adopted-text-xml.mjs` has a separate native EP `SDOCTA` contract. `readAdoptedTextXml(bytes, {work, language, sourceUrl, fetchedAt})` requires one XML distribution declared for that language on the exact adopted-text work. Its `blocks` retain text, separate `NO.P` labels, UTF-16 emphasis ranges and inline note-reference offsets. Notes preserve their source text and ordinal; absent display labels remain null. `textLists`, `components` and native `containers` have half-open block extents and exact XML paths. Component `content` contains only directly owned blocks; extents include nested components. Repeated adopted `AMEND` pairs retain separate old/new ranges, including explicit empty columns. Hidden text is excluded, unknown structures/attributes produce gaps, and unsupported objects retain U+FFFC. `nativeComplete` describes supported XML extraction only; `fidelityGaps` and the held source preference remain separate. This contract is not passed to proposal placement or amendment-list ingestion. Enabling it in readers requires independent DOCX-equivalence and rendering validation; issue dates never prove equivalence.

## Tree and source positions

The result contains `parserVersion`, `sourceHash`, exact source context, `paragraphs`, ordered `units`, notes, links, objects and explicit `gaps`. `src/proposalTypes.ts` describes the frontend projection.

The bounded DOCX projection retains at most 500 body hyperlinks, 500 referenced notes, 4,000 UTF-16 code units per note and 10 hyperlink spans per note. Actual truncation produces a gap with the source part/path and affected note or paragraph. Only owning paragraphs and their containing units lose completeness; retained text, objects and links keep their positions.

- Unit `path` segments preserve labels, suffixes and scripts. Chapter, section and title containers remain in the tree. `proposalCandidates` permits an article/annex/recital address to omit its preceding heading containers, returning every candidate when the result is ambiguous. A bare annex’s unnumbered lead has an internal implicit paragraph container; its published point addresses omit that unpublished level. Explicit numbered paragraph levels remain distinct.
- `extent: {start, end}` is a half-open range of paragraph indices including descendants. `content` identifies directly owned paragraphs; `spans` supplies exact UTF-16 slices. An instruction and inline replacement can share a paragraph through disjoint slices.
- Memorandum, preamble, signature and financial statement remain separate regions. Articles, including binding final articles, belong to the legal body. A non-normative region is never treated as an article container.
- Quoted replacements have `scope: 'quoted'`, their outer `instructionPath`, and an `underlyingPath` that inherits the enclosing instruction's article/annex context. A quoted Article 9 cannot become an outer proposal Article 9. Inline openings retain quoted scope across paragraphs; nested term quotations and possessive apostrophes do not close it. A possible trailing apostrophe retains an `ambiguous-quotation-boundary` gap unless the next source instruction or annex heading independently verifies the boundary. A consecutive amending instruction with the same list syntax and style can end a replacement whose source omits its closing mark; `closingBoundaryBasis: 'instruction-sequence'` records this. Numbered continuation paragraphs with distinct inner list syntax stay quoted after a premature closing mark. An explicit replacement instruction can establish an omitted opening mark; `boundaryBasis` records this. Numbered instruction prose takes precedence over a short heading prefix.
- Tables retain rows, cell paragraph references, column spans, horizontal/vertical merges and nested tables. Empty tables retain their source anchor. Cells are not concatenated into legal paragraphs.
- `complete`, `contentComplete` and `structureComplete` distinguish object/text fidelity from structural gaps. Inspect the selected unit and its objects as well as document-wide status. An unresolved logo can make the whole document incomplete while a legal provision remains readable.

IDs are versioned hashes of source identity, source content, language and item plus the structural path. They identify a particular parser/source revision; they are not official legal-unit identifiers. For a supplied text projection `sourceHash` hashes the supplied paragraph text, rather than claiming to hash its unavailable DOCX bytes.

Results use a bounded process-local LRU keyed by exact input hash, parser version, language, item, identity and source URL. Up to eight immutable results occupy an estimated 64 MiB budget. Consumers must copy a result before modifying it. Changes to parsing semantics require a parser-version bump.

## Internal comparison metadata

`server/comparison-metadata.mjs` consumes an existing amendment record and a bounded native observation. It is a standalone helper; readers, endpoints and placement do not call it. `sourceObservation` retains the declared distribution separately from the response URL, language, retrieval time, response hash and representation. Its identifier hashes the complete observation tuple; missing declarations remain null.

`comparisonMetadata({observation, native, amendment})` expects source-ordered content rows with both cells, including empty paragraphs. The caller supplies the hashed native part, namespace aliases, one-based qualified sibling paths, the preceding amendment heading, exact paragraph text, native run/separator ranges and completeness/object evidence. Read and verify these from the source before calling the helper. Recital numbers and auxiliary same-number candidates cannot establish amendment identity. The helper bounds rows and text and checks identity and exact field mapping; it does not read files or select sources.

Each field retains its existing text plus the complete native column, disjoint paragraph/join regions and a reversible UTF-16 whitespace map. Removed whitespace stays in the map; punctuation and URLs remain literal. Markers and labels annotate their parent regions. Typed Word bindings remain source-layout candidates, with missing references and duplicate labels explicit. Unsupported objects and unmapped fields remain unresolved. `xhtmlNoteMetadata` separately retains exact native forward/backlink edges and occurrence arrays from a complete source observation. Neither helper supplies legal coordinates, note equivalence, composite classification, deletion semantics or shared-note application.

## Numbering and candidate resolution

Proposal extraction uses the shared `docxContent` numbering resolver through `proposalNumberingLabels`, which adds level and format metadata for proposal hierarchy. Concrete numbering instances sharing an abstract list continue that list unless an explicit `startOverride` or overridden level start restarts it. Formatting-only overrides continue the list. `lvlRestart` uses its one-based trigger from the abstract definition; zero prevents restarts, and an omitted or invalid trigger uses the preceding level. Independent abstract lists remain separate. This recovers the CBAM annex's published `(1), (2), (3)` sequence and makes amendment 8's `Annex I / paragraph 1 / point 2 / point a` address unique.

DOCX paragraph properties retain the concrete and abstract list IDs, level and number format. These levels, explicit point styles, or numbered Roman items in `TextN` styles establish point depth. Styled alphabetic and Roman labels retain either their parenthesized or dotted source prefix. Roman-compatible letters alone never establish a deeper list: consecutive alphabetic labels in the same `TextN` style remain siblings, including `(c)` and `(d)`. An unstyled Roman item with uncertain depth retains an `ambiguous-point-level` gap and a conflicting path. A point style alone cannot close a quotation: quoted lists can reuse outer instruction styles. A following numbered instruction can establish that boundary. Croatian low-opening quotations close with the published right double quotation mark. Compact decimal article headings such as `Article2` retain a separate article boundary.

A visible `Ö` result from a native `CRMarker` QUOTE field can precede a numbered recast subdivision. Its source path supplies label-prefix metadata so the following number establishes the subdivision boundary. The marker and all source wording remain unchanged; an ordinary literal glyph or hidden field supplies no such evidence.

The row immediately after an article heading is its title when it has an article-title style or centred Word formatting. A continuation with less Word text indentation than the final point belongs to the enclosing paragraph; equal indentation keeps it inside that point. Standalone terminators stay with the preceding instruction. A bare, heading-styled annex retains an empty label value rather than acquiring a Roman numeral. Published literal labels and explicitly disabled automatic numbering remain unchanged.

A numeric amending instruction ending in a colon can own consecutive lettered instructions even when Word repeats the same point style at both levels. The child sequence starts at `a`, retains each complete instruction and its quoted wording, and ends when the next numeric instruction starts. This recovery preserves literal labels and never overrides explicit Word numbering.

A centred, fully bold subtitle immediately after an article heading remains an article title even when its Word style is Normal. It does not create an implicit paragraph or turn the following explicitly numbered paragraphs into list points. Unnumbered definition introductions retain their numbered points.

Literal duplicate labels under the same parent remain separate units with `pathConflict: true` and distinct occurrence IDs. `proposalCandidates` returns **all** exact candidates, ignoring the internal occurrence suffix; it never chooses by wording or invents a number alias. A caller may compare the amendment's original wording against exactly those candidates and record a unique normalised match. Otherwise the target stays unresolved. Labels repeated under different parents are independent.

`parseTargetLabel(label, language)` returns `{raw, language, segments, complete, unparsed, underlyingLabel}`. Its second line is retained separately as the underlying-act label. Unsupported fragments keep `complete: false`. Observed EP forms include spaced multiletter point suffixes, suffixed Roman annexes, negative labels with terminal dots, Finnish split recital nouns, Dutch `Paragraaf`, Portuguese `k‑A` point suffixes and the Greek introductory-part selector. Bare title, introductory-part and annex selectors use the published 24-language vocabulary. Shared nouns retain their explicit parent context, including Finnish points under an annex and Lithuanian genitive annex addresses. Scripts remain distinct. Greek serial point labels retain the three-letter forms documented in the Commission DGT English Style Guide, Annex 3 (`ιστ`, `κστ`, through `πστ`); these are whole source labels, with no inferred Latin equivalent. Greek uppercase heading vocabulary and Greek Ι/Χ glyphs used for Roman heading ordinals have explicit grammar rules; `sourceValue` retains the original glyph spelling. A source article heading without a number remains unlabelled with a gap. The 24 language grammars preserve observed EP discrepancies: omitted paragraph levels, Portuguese `Article I`, Dutch annex `1`, and the Slovak annex point `1` are not silently rewritten to another path. `unitLabel(unit, language)` formats one segment for display; it does not translate source wording.

French Latin numbering follows the [Interinstitutional Style Guide, section 3.3.2](https://style-guide.europa.eu/fr/content/-/isg/topic?identifier=3.3.2-additions-and-numbering) and [Annex B](https://style-guide.europa.eu/fr/content/-/isg/topic?identifier=annex-b-use-of-italics): the published inventory through `quinvicies` and compounds of up to three suffixes retain distinct paths. Long suffixes work in literal source points and paragraphs as well as target labels. Insertion ordering keeps `1 bis bis` between `1 bis` and `1 ter`; raw source labels remain unchanged. Spaces between compound suffix tokens remain part of their identity: `quater decies` is distinct from the single suffix `quaterdecies`. Unknown compact compounds are not reconstructed. The extended vocabulary is French-specific and does not translate identifiers across languages.

## Mathematics and other objects

`proposal-math.mjs` converts fractions, sub/superscripts, radicals, n-ary operators, delimiters, matrices, equation arrays, text runs, functions, limits and allowlisted bar/hat/tilde/dot accents to a JSON MathML tree. `ProposalMath` creates allowlisted React elements and escaped text. Permitted attributes are `accent="true"` on `mover`, `accentunder="true"` on `munder`, and `mathvariant="normal"` on `mi` for explicit upright identifiers. Following [MathML Core](https://w3c.github.io/mathml-core/#dfn-mathvariant), validated OMML script/style pairs encode bold, italic, script, fraktur, double-struck, sans-serif and monospace Latin letters and supported digits as [Unicode mathematical characters](https://www.unicode.org/charts/PDF/U1D400.pdf), including the Letterlike Symbols exceptions. Unmapped characters remain unresolved. Fixed operands have container-specific names and cardinalities; repeated delimiter elements, matrix rows/cells and equation-array entries remain ordered. Duplicate, unexpected or hidden operands make the whole equation unresolved. Unknown run properties, malformed values and unsupported combinations remain unresolved. Upstream markup is never inserted into the DOM.

Unsupported structures retain U+FFFC, source offsets, `complete: false`, the unsupported element names and an official-document link. Embedded pictures can additionally carry a bounded image asset and their original media relationship. Readers display supported raster pictures, including in notes and tables, while drawings retain the unresolved wording convention. Grouped shapes, unsupported picture transforms and vector media keep the original-document fallback. Image rendering never changes provision completeness or establishes equation or wording equality. A plain text match containing U+FFFC cannot establish equation equality: callers must compare the corresponding safe object structures or leave the match unresolved.

Proposal notes retain their text, links, anchors, `complete` state and positioned `objects`. Each note has a `source: {part, path}`; its objects carry the owning `note` ID, `sourcePart`, full source `path`, note-local `paragraph`, paragraph-local `paragraphOffset` and UTF-16 `offset` into the displayed note text. Custom labels are removed only from the displayed offset. `objects` at document level includes body and note objects; use `paragraphs[].objects` for body-only counts. Unconverted or unverified notes make their referencing paragraphs and owning units incomplete and add an `incomplete-note` gap. Unsupported body equations add `unresolved-math`.

`ProposalNotes` renders these objects with `ProposalMath` through the shared `DocumentNotes` list. It preserves note IDs, reference links on equations and symbols as well as surrounding text, and UTF-16 positions. An unresolved linked object retains its original link separately from the official-document fallback link. Ordinary `DocumentNotes` consumers keep their existing text renderer.

The same XHTML adapter reads dated consolidations. Explicit `no-parag` labels establish numbered paragraphs; grid-list columns establish points, including Polish `a)` labels. Subsequent unnumbered paragraphs remain with their source owner. Consolidated final clauses (`fnp_*`) remain separate from the last article and annexes. Consolidation change markers stay outside legal wording; unsupported notes and objects make the affected passage incomplete. Existing-law placement uses the inner act/address and a verified dated language version. Published amending instructions and their replacement slices retain separate offsets; the outer proposal address never selects a provision in the law.

## Matching policy

`normaliseForMatching(text, {stripNumbering = true, stripTerminators = true, numberingPrefixes = []})` produces an alignment key while preserving the original strings in the proposal and amendment records. It applies NFC, removes soft hyphens, folds NBSP/narrow NBSP to spaces, maps typographic apostrophes and quotes, and maps typographic dashes to `-`. It strips an enclosing quotation boundary, decimal and single-letter numbering prefixes, and trailing list full stops/semicolons. Parenthetical words remain meaningful. Multiletter labels require an exact prefix supplied for the corresponding line in `numberingPrefixes`, taken from parsed numbering metadata. `stripNumbering: false` and `stripTerminators: false` retain those features.

For CBAM report A-10-2025-0085:

- Amendment 5's quoted source ends with a differently positioned quote/semicolon; its wording has the same key.
- Amendment 7 ends `declarant.’;` in the proposal and `declarant.;’` in the EP comparison column; both retain the same words and key.
- Amendment 8's sentence has a quotation boundary and terminator in the proposal that the comparison column serialises differently.

The normaliser does not fold case, remove accents, transliterate suffixes, change dates or numbers, delete words, or use fuzzy matching. The real source pairs and source URLs are in `server/fixtures/proposal-matching-excerpts.json`.

Closers may precede whitespace and a full stop or semicolon, including Greek `·`. Nested terms include repeated double marks, Finnish `’…’`, Hungarian `»…«` and Slovenian `,…‘`. The same sources contain omitted, repeated and premature delimiters; list ownership and source boundaries remain necessary alongside punctuation. The Danish amendment phrase `foretages følgende ændringer` and Maltese insertion verb `jiżdied` in COM(2024)183 establish consecutive outer instructions after omitted closers; complete adjacent instruction excerpts are retained in `server/fixtures/proposal-instruction-boundaries.json`. These are observed conventions, not a claim that every document uses one pair per language.

The offline fixtures contain selected public Commission DOCX paragraphs and EP amendment labels with exact source URLs, languages, hashes and retrieval dates. Full documents remain outside Git. The CBAM act/annex, AI Act annex, all 24 label grammars, instruction nesting, shared-list restarts, MathML safety and punctuation pairs have offline tests. The large-text regression parses exactly 8 MiB within a 15-second CPU budget and 60-second wall guard under a 256 MiB V8 heap cap; cache hits reuse the immutable result.

The document-context reader uses this projection when the selected amendment column explicitly names the Commission proposal. `proposal-placement.mjs` resolves proposal-level addresses, checks original wording and returns exact source-row/character splices. Without a structured target path, the published location heading from the same amendment document and language is the address. Insertions follow a complete preceding sibling subtree; alphabetic/Roman suffixes retain their exact base and suffix, and a new unsuffixed point requires its existing immediate predecessor. A first Roman point can start below a verified childless point. Negative new point labels (-a or -1) use a complete existing parent and the verified start of its first sibling; duplicate labels need a unique whole-unit wording match under the same parent, or a partial match unique in the whole document. A single candidate inheriting a path conflict also requires document-wide unique wording. A missing final path can use its deepest unique ancestor only for document-wide unique wording covering whole source lines. Omitted levels must not contradict explicit labels of the owning proposal units or provision references in their owning instruction; agreeing or silent evidence permits recovery. A resolved address with different wording and a failed numbered-subparagraph check still withhold. Addresses without an Annex segment exclude annex content items. Proposal subparagraphs have no labels: `subparagraph N` resolves its containing provision and requires a unique wording match inside that subparagraph's own paragraphs (the lead text for N = 1, the (N−1)th subparagraph child otherwise). An English “introductory part” address uses the provision’s own lead bounds (as for subparagraph 1) and requires unique wording inside them. An “Article N – title” address selects only an article title child. A first-subparagraph address followed by a point resolves that point within the lead/list group. An outdented continuation closes the last point and starts the next subparagraph; an insertion after the last point stays before that continuation. Later subparagraphs after points require a directly owned continuation whose Word indentation establishes the return to the provision. In XHTML, an explicitly addressed later subparagraph can own a consecutive point list after its native colon introduction; the next directly owned paragraph ends that list. The complete provision and list boundaries must be supported. Published article-to-point addresses may omit the parser’s single implicit paragraph container; placement traverses that container only when the article and its sole body paragraph are unambiguous. Explicit paragraph labels remain part of the address. Quoted underlying-act paths never select an outer unit. An explicit English new paragraph Naa can resolve between existing quoted paragraphs Na and Nb inside its unique complete outer instruction. The same-language underlying act must match the nearest enclosing statutory amending instruction, both source siblings must share the complete inner parent address, and their full extents must be adjacent consecutive source rows. This local nested suffix family follows [ISG 3.3.2](https://style-guide.europa.eu/en/content/-/isg/topic?identifier=3.3.2-additions-and-numbering); it does not change the ordinary suffix order. The published target and proposed label retain their raw spelling, including the attested target `2a a` alongside proposed `2aa`. Terminal boundaries, missing siblings, incomplete quotes and mixed instruction/legal wording remain unresolved.

Placement disables the normalizer's generic numbering stripping. Only prefixes established by parsed unit labels are removed from comparison keys. Source text, links and note offsets remain unchanged; the reader uses the exact source slice for the original side of the diff. An equation in either amendment column or the changed source extent withholds placement because the columns do not supply comparable object trees. Unchanged equations use the MathML renderer. Parser scope and numbering gaps must be resolved before relying on placements in affected source structures.
