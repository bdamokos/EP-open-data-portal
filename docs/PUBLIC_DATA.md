## Transparent website processing

Portraits use only the public `https://www.europarl.europa.eu/mepphoto/{photo-id}.jpg` URL supplied by the exact member profile (or its existing member-ID fallback). They are fetched anonymously on demand, with redirects disabled. With `ODP_CACHE_DIR` configured, each saved binary record retains the exact member ID, source URL, retrieval timestamp, MIME type and a SHA-256 integrity checksum. Portraits have no language variant. Saved images are fresh for seven days; an expired image remains visible during refresh or if that refresh fails. At most two background refreshes run at once, with 120 queued member IDs; overflow remains stale until a later request can schedule it. Refresh profile reads use the shared upstream queue's background priority, leaving capacity for interactive text requests. Failures back off for five minutes and never become empty image records. The cache retains at most 128 MiB including record metadata and 2,048 records; it prunes by oldest save time and does not download the roster in advance. Each download is bounded to 2 MiB while streaming. The browser's existing six-hour private cache remains in place. Cached portraits stay outside Git and retain the source website's image terms.

OEIL summaries are parsed from visible HTML, linked through the exact procedure reference returned by the API. The adapter records the source page, retrieval date, language and summary stage. It does not invent a summary when none is supplied.

Parliamentary documents are read from official distributions linked by the Open Data API. DOCX is processed locally with bounded decompression; there is no document conversion service. Extraction reads `word/document.xml` and optional style, numbering, settings, footnote and endnote XML parts within a shared 4 MiB decompression limit. Automatic paragraph labels and referenced notes are retained, with separate footnote/endnote series, declared number formats and section restarts. Page-dependent note restarts remain explicit gaps. Unsupported numbering and missing notes are explicit extraction gaps for comparisons. Hidden text (`w:vanish`), including inherited translation-marker styles and default paragraph/character styles, is omitted; visible text, run breaks and non-breaking hyphens are preserved. Style visibility is resolved once per style within each extraction; cyclic inheritance is rejected. Speaker headers, cover pages and document bodies remain distinguishable. Extraction-version changes refresh saved text only when the document is requested. The bounded English example in `server/fixtures/motion-text-live-20261016.json` retains the opening paragraphs and hidden styles of B-10-2026-0431, checked anonymously on 16 October 2026, with its exact source URL and retrieval time. Footnotes and http(s) hyperlinks retain exact marker positions and text spans. Up to 500 notes of 4,000 characters are kept for reading; comparisons report a gap if referenced notes exceed those bounds.

The public Multimedia Centre site uses `https://api.multimedia.europarl.europa.eu/o/epmp-frontend-rest/v1.0/media/{recording-id}`. The official player uses `wss://websockets.services.eup.glcloud.eu/content-manager/api/v1/socket.io/?EIO=4&transport=websocket`, namespace `/content`, event `join:event`, with the recording’s public `commonId`. These interfaces are exposed by the public website and are undocumented. The adapter sends no password, cookie, authorization header or forged Origin. It accepts only `PUBLISHED` content matching the recording identity and times.

The client verifies the requested audio representation before playback. Missing, ambiguous or mismatched tracks leave the player closed. The adapter downloads metadata, not video segments or an audiovisual archive. Automatic recording-catalogue search is unavailable; a catalogue needs source-page URLs and retrieval dates. Missing catalogue coverage is shown explicitly.

## References in questions and answers

Readers recognise exact official numbers: EU acts (pre- and post-2015 forms), ELI, CELEX and Cellar links, COM/SWD/JOIN documents, procedure numbers and question numbers. Fixed numbering rules turn each into a lookup key; titles and name similarity are never used, and unrecognised forms stay plain text. A document hyperlink to an official target identifies its linked text ahead of text patterns. A footnote marker opens a card only when its footnote identifies exactly one work; a citation followed by a footnote is reported as confirmed by it or as pointing elsewhere, never substituted. Answer PDFs carried the same link targets as their DOCX in 21 answers sampled on 16 October 2026, so only DOCX is read.

One SPARQL query per reader (at most 40 references) resolves CELEX numbers and Cellar works; a reference links only when exactly one work matches. A missing in-force flag stays unknown. Question numbers in term-change years (2014, 2019, 2024) link only when exactly one candidate exists and no lookup failed. Results are cached in `ODP_CACHE_DIR/legal-references-v1` for seven days (missing: one day); unavailable or stale-source results are labelled and not saved. Dossier summaries come from OEIL for the exact procedure, preferring final-act then proposal summaries. Acts before 16 July 2024 are marked as preceding the current term. Official Journal position links (`uri=uriserv:OJ…`) are not resolved.

Publications Office and OEIL requests have separate admission queues from Parliament, each retaining 2.1-second spacing and two active requests. A source's 20-second budget includes admission, same-origin redirects and body reads; a reference batch shares one 28-second budget and stops further lookups on expiry. A detached reader leaves surviving shared cache work bounded by its source budget. Failed lookups retain readable text and available saved descriptions, with an explicit retry control.

## Derived views

Analysis periods in questions, topic timelines and MEP speech clouds include **Current term**, from 16 July 2024 through today (Europe/Brussels), or through the chosen Until date where available. Numeric API windows may span any number of days within that term; there is no fixed 365-day maximum. Both boundaries are inclusive. Shorter presets remain available.

The [official API specification](https://data.europarl.europa.eu/api/v2) documents speech start/end dates and parliamentary-term selection without a 365-day span restriction. An anonymous, one-record check on 15 October 2026 spanning 16 July 2024–15 October 2026 returned a speech dated 16 September 2024; exact request and identifier are retained in [date-range-check.json](date-range-check.json). Questions and procedure timelines filter the existing saved index; selecting a wider period does not start a corpus download. Existing record, text and paging budgets remain, with truncated or incomplete coverage labelled separately from the date range.

Question topics use titles and bounded already-cached English bodies. Repeated phrases remain together; routine parliamentary terms are filtered. Counts deduplicate questions and co-authors. Country vocabulary comparisons use the same question selection and retain coverage and sample-size limits.

Topic timelines display the saved procedure's official `process_title` in the selected language, falling back to English with its language retained. No separate short-title field is supplied; long titles collapse visually and expand on selection. Status uses exact dated `PUBLICATION_OFFICIAL_JOURNAL`, `SIGNATURE` and `PLENARY_ADOPT_POSITION` activities, in that order, through the source retrieval date. It describes the latest saved milestone even when viewing an earlier activity period. Parliament's position does not establish final adoption; absent milestones mean **Adoption not recorded**, not that the procedure is pending. Each dossier links to its public API record and retains its retrieval time. The existing index writer upgrades older projections within its normal request budget; no page view starts an indexer.

Speech clouds use supplied body text in the selected language. Counts describe distinct speeches mentioning a term; a single-speech cloud uses occurrences. Clicking a term opens exact source IDs and highlights literal whole words or phrases without rewriting the text. Machine translations are labelled. Absent translations are not generated.

In an agenda item's **Who is involved** list, transcript headers identify chairing remarks per speech, including original-language chair labels retained in translated fragments. A person whose linked contributions are all identified as chairing is excluded from that list and its contributor demographics. A separate speech, written statement or documented item role retains them. Missing headers do not establish chairing. The distinction updates as the existing speech cloud or reader supplies headers; transcripts remain readable and no additional speech download is made. The bounded [header examples](../server/fixtures/chair-headers-20261015.json), retrieved on 15 October 2026 from the anonymous speech API, retain exact person/activity IDs, request URL and language; bodies are omitted.

The plenary sitting catalogue pages through the official `/meetings` metadata for every year from 2024 through the current Brussels year, then keeps every sitting on or after 16 July 2024. Agenda, plenary word-cloud and participation sitting/week selectors share this catalogue; neither past sittings nor published upcoming sittings have a count cap. Plenary agenda, participation and word-cloud views default to the week containing the latest held sitting; single sittings remain selectable and exact item links retain their sitting. Weekly agendas preserve day headings and unavailable-day gaps. Only the selected sitting or week loads its details. Weekly speech clouds query each held sitting separately, with total page and XML budgets scaled by the number of held days (at most five), and preserve partial-coverage labels. If Parliament supplies no historical agenda, the selected date and full catalogue remain accessible with an unavailable-agenda message. A complete catalogue means the official list was paged to its end, not that agendas, speeches or the saved activity archive are complete. The API supports comma-separated years; a 15 October 2026 check returned 157 meetings across 2024–2026 in four pages (50, 50, 50, 7).

Plenary participation uses actual named voters and exact speech-parent links. Unavailable observations are null rather than fabricated zeroes. Whole-sitting pagination compares unique IDs with declared totals and reports partial coverage for overlaps or missing records.

MEP motion cards show the final outcome for the exact motion document, using the anonymous `/plenary-documents/{id}`, `/meetings/{sitting-id}/vote-results` and `/meetings/{sitting-id}/decisions` API routes. Saved document projections retain `inverse_based_on_a_realization_of` links to vote results or voting agenda items, and joint motions' `is_derivative_of` links to their source motions. A decision must belong to the linked vote result and explicitly identify the same B10 or RC-B10 reference in its English heading/reference. Only whole-motion decisions or standalone document outcomes qualify; amendment and procedural decisions do not supply a motion's result. Every declared decision child of that result must be present before an outcome is assigned. Conflicting final decisions and missing records remain unavailable.

Outcome requests include every voting method and use `filter-output=voters` to omit named voter lists. Show-of-hands decisions can supply an adopted/rejected outcome without numerical totals; absent counts remain null. Original and joint texts are resolved independently, and related joint motions are linked only through `is_derivative_of`. Each outcome retains the exact document/decision IDs, source request URLs, retrieval dates and the English reference language used for matching. The bounded example in `server/fixtures/motion-outcomes-live-20261015.json` retains the 8 October 2026 sitting's outcome relationships and excludes named voters and unrelated graph nodes.

Cards label a lapsed original with an exact joint-motion relationship as replaced, keeping the official “Lapsed” status in the expanded view. Each text retains its own reference, status, date and available totals. Joint authorship is checked independently against that document's exact author/person records; a replacement link never credits the original author on the joint text. Missing authorship is labelled as not recorded. Outcome source URLs remain in the data response; the interface does not link machine-readable decision records as voting results. Related-text links open official PDF/DOCX distributions and label the format and language, preferring the requested language, then English, then another available language. Without a readable document URL, the reference remains plain text.

The existing activity-index writer acquires these records through its shared request queue, once per sitting for all authors. Loading a profile performs no vote-source request. Recent sittings refresh after six hours and older sittings after seven days when the daily job runs; recent motions without vote links are checked again after a day. An upgrade refreshes older motion projections without resetting the index or its page cursors. Failed refreshes retain the published generation and saved outcomes. Source gaps remain distinct from a motion being rejected or awaiting a vote.

Both published final-motion labels, “Motion for a resolution” and “Motion for a resolution (as a whole)”, qualify when the exact document reference and relationships match. An incomplete refresh retains the last complete sitting and its original source timestamps. Missing IDs and request provenance for the failed attempt are stored separately as `lastRefreshFailure`, exposed on resolved outcomes as `refreshFailure`, and retried by later background jobs. A first load with incomplete records retains its coverage gaps.

Original-to-joint relationships use a derived SQLite index. Source insert/update/delete triggers maintain it in the same transaction as the source record, including generation copies and pruning. Existing retained sources are indexed once under the writer lease. Page requests use indexed exact-reference lookups rather than scanning the document collection for each motion. After rollback, older workers leave new vote tasks pending for a supporting worker and continue serving saved activities.

Wording comparisons fetch only the selected motion pair and, when requested, its procedure and adopted-text records. `/procedures/{id}` supplies candidate adopted document IDs through `created_a_realization_of`; `/adopted-texts/{id}` must explicitly `adopts` the exact joint motion. Missing or multiple matches remain unavailable. Both texts use a common published DOCX language, with any language fallback, source URLs, retrieval dates and stale sources shown. The comparison excludes recognised cover material, normalises layout whitespace and retains wording, punctuation and referenced notes. Exact passages can be aligned after renumbering; other paragraph matches require a conservative reciprocal word-overlap match. Ambiguous rewrites remain separate passages. Alignment does not establish authorship or negotiating influence. Comparisons are bounded to 600 paragraphs and 300,000 characters per text. The bounded source excerpts in `server/fixtures/motion-comparison-excerpts-live-20261016.json` preserve the literal `59.58`/`59,58` difference in RC-10-2026-0441 and TA-10-2026-0339; both English UK source DOCX files and PDFs were checked on 16 October 2026. The separator difference represents the same numerical value; its editorial cause is not supplied.

### Speech interventions and exchanges

Anonymous API checks on 15 October 2026 confirmed blue-card questions, answers and reactions in `recorded_in_a_realization_of[].api:xmlFragment.en` under `oralStatements/*/from/process`. The activity type remains `PLENARY_DEBATE_SPEECH`; a `question` XML element alone does not identify a blue card. Classification reads the supplied English header, including Parliament's labelled machine translations, and never searches speech bodies for an intervention type. Unreadable or absent headers remain unclassified.

English API fragments sometimes retain a German process label. The parser also recognizes the supplied `Frage`, `Antwort` and `Reaktion` labels for the `blaue Karte` procedure. The saved examples include three such headers from a complete 550-record member pagination check. An absent header keeps unobserved intervention counts null and the statistics coverage partial.

The debate sequence joins exact `inverse_consists_of` event IDs to the parent's `consists_of` IDs, ordered by document `numbering`. An A → B blue-card question → A blue-card answer sequence creates an exchange; subsequent reactions by those speaker IDs and further question/answer pairs remain attached to A's original contribution. These are derived links: the API has no explicit reply-to speech field. Numbering gaps, duplicate numbering, unmatched speaker IDs, another ordinary speech or an unclassified contribution stop reconstruction. A missing record elsewhere in a debate does not suppress an intact local exchange. Chair interventions may occur between linked contributions. Speech and question identifiers, group designations and names are never joined by text similarity.

Catch-the-eye is also published as a `PROCEEDING_ACTIVITY` narrative section, with start and end markers. The supplied English text can say `Catch-the-eye procedure` or, in a machine translation, `On-demand interventions`. Only an uninterrupted numbered section between both markers marks its oral speeches as catch-the-eye. This identifies a debate phase; it does not assign those speeches as replies to an earlier speaker.

Opening **Debate & exchanges** retrieves the selected speech and up to four exact parent events, plus the selected sitting's `/speeches` pages with `include-output=xml_fragment&language=en`. Procedure records are included so section markers are retained. Requests use the existing shared queue and public cache. A sitting is bounded to four pages of 500; up to eight selected sittings share in-flight requests for 30 minutes. Source URLs, retrieval times and missing child IDs accompany the result. Connected text uses the existing speech reader in the chosen language.

The shared queue spaces starts by 2.1 seconds, permits two active operations and reserves one slot for interactive reads. Interactive requests wait at most ten seconds for admission or when joining an existing background read; a cooldown interrupts that wait without cancelling shared background work. Upstream 429/503 responses pause new requests; numeric and HTTP-date `Retry-After` values are honoured within 30 seconds–30 minutes (60 seconds when absent). Background retries release their slot and rejoin the queue. Cached text remains readable during the pause. Failed debate sections offer **Retry sequence**, with a countdown during a known cooldown; retry bypasses the browser's cached partial result and reuses successful source records.

API reads have a 30-second absolute response budget, extended to 50 seconds for debate sequences and motion comparisons. Queue waits, shared-read waits and source body reads consume that same reader budget. Disconnecting a reader removes its queued work; a cold ODP job is cancelled when its last reader leaves, while other readers and background cache owners retain shared work. ODP downloads reject redirects and stream at most 12 MiB. Existing cached records remain available after cancellation. JSON responses include `Server-Timing`; deadline logs record the route, elapsed time, instantaneous EP queue state and event-loop utilization for runtime diagnosis.

`had_participation.participation_in_name_of` supplies the historical organization ID for **On behalf of** labels. Political-group counts use explicit group IDs, rather than the MEP's present group membership or the mere appearance of a group in a header. NI is not counted as a political group. MEP statistics count group designations, blue-card questions, answers and reactions separately. **Blue cards answered** is the number of recorded replies, not a tally of declined requests or every card displayed in the chamber. Catch-the-eye section classifications are available in the debate sequence rather than a term-wide count from individual headers.

Statistics initially read one 50-record member page; **Count all contributions** continues sequentially, up to 20 pages. Counts cover term 10 oral contributions and written statements and deduplicate exact speech IDs. Unique IDs are checked against declared totals; incomplete or overlapping pages retain a partial-coverage label. Up to eight member selections are held for 30 minutes. Neither statistics nor debate viewing starts an indexer, downloads a corpus in the background or writes the activity database. The bounded projected live example in `server/fixtures/speech-interventions-live-20261015.json` retains source requests, dates, exact headers and section markers, with complete text for one exchange.

Numbered debate subitems retain their full parent IDs. Blue-card counter-replies count as reactions and remain in their original exchange. If a member selection is evicted or expires during pagination, the response restarts at page zero and the browser follows the returned next page, reusing the ordinary public-source cache. A walk allows two automatic restarts; each walk remains bounded to 20 pages.

### Outside voices

The Outside voices view uses oral `/speeches` records from terms 9 and 10. The existing activity worker shares its current-term speech catalogue and adds bounded monthly term-9 queries. It compares each speaker with `/meps/show-current?mandate-date=YYYY-MM-DD`, retaining the exact dated roster queries. It does not use today's roster to classify older contributions. Historical MEP speech metadata is discarded after that check; historical outside-speaker records remain. Written statements stay outside this view.

Only outside candidates load speaker headers through `/speeches/{id}?include-output=xml_fragment&language=mul`, with an English fallback when no identity is returned. Exact person references in the XML must match the API participation. Original-language tags take precedence over translated headers; original roles can still conflict. Names, raw roles, XML language tags, request URLs and retrieval dates are retained separately from derived capacity groups. Groups use documented source-role patterns, with unmatched roles under Other speakers; same-day disagreements remain visible. Language-filtered detail responses retain the catalogue's titles and the separate header source. Speech text and recording lookup remain on demand in the existing reader.

Agenda items follow `speech.inverse_consists_of → event.activity_id`, including `PLENARY_ACTIVITY` formal and special events. Dossier links use exact procedure URIs in the actual event's `inverse_consists_of` or its `inverse_was_scheduled_in` relationship. COD/CNS are legislative; other or unavailable procedure types remain distinct. Speeches, distinct person-by-agenda appearances and sitting days are separate measures. Repeat appearances are recorded speeches, not invitation counts. Committee prepared statements and hearings are not counted as plenary speeches.

The public API's compact metadata and headers are saved by the existing single leased worker and generation mechanism. Reading the directory or a speaker page makes no upstream request. Header, historical-catalogue, roster and agenda failures retry three times, then remain explicit gaps for the next generation to retry; they do not permanently prevent ordinary activity publication. Unnamed speakers, unlinked contributions, pending tasks, source gaps and the 50,000-record response selection limit keep coverage partial. The interface has one short coverage label, with sources on demand.

Older website speech references use the published hyphenated document number where the numeric notation is the legacy short form. Verified examples are `CRE-9-2021-11-24-INT-3-103-0000_EN.html` and `CRE-9-2023-09-13-INT-3-110-0000_EN.html`; modern numeric references are preserved. No archive-wide changeover date is assumed.


## Full-text corpus

With `CORPUS_ENABLED=true`, one leased background worker stores current-term texts in `corpus-v1.sqlite`, separate from the activity index's refresh generations:

- Speeches come from the `/speeches` list with `include-output=xml_fragment`, read month by month in pages of up to 25. Oversized pages are retried at half size. A search reference without its record is fetched individually.
- Question and answer texts are extracted from the official DOCX distributions listed by the saved index records, using the same bounded extractor as reading view. The original languages and English are fetched before other languages.

Each text keeps the exact source ID, fragment key or file language, source URL, retrieval and last-check times, a SHA-256 digest and its translation status. Speech XML is kept zstd-compressed. A fragment marked `mtec` is recorded as machine translation; most non-original speech languages are. `CORPUS_LANGUAGES=primary` keeps only originals and English. Speech months from the last 120 days are rechecked weekly, and the current week daily, because translations arrive later. Unchanged text is not rewritten. Question records are rediscovered from the index every six hours. Requests are spaced by `CORPUS_REQUEST_INTERVAL_MS` and use the shared background upstream queue.

Search uses SQLite FTS5 with Unicode tokenisation. Latin-script diacritics are folded, but Greek accents are not. User input is limited to quoted words and phrases. Member filters and member IDs join exact `source_id` values to the attached activity index: speakers for speeches, authors for questions and answers. Results carry their coverage state, and backfilling results are labelled incomplete. Collection stops at `CORPUS_MAX_DISK_MIB`; there is no eviction yet.

## Saved examples and supporting data

`server/fixtures` contains bounded public API responses and public OEIL HTML for tests. Each example retains source attribution or provenance. Public API records can contain identifiers named `notation_codictPersonId` or similar; these are fields returned by the open API, not calls to another service.

`outside-speakers-20261016.json` contains compact projections of 20 public speech observations, exact agenda records and four dated rosters, retrieved 15–16 October 2026. Speech bodies are omitted from the projected XML header fragments. Every observation retains its original public request URL and retrieval time. The test fixture is not a runtime catalogue.

Committee labels come from the public corporate-bodies API. Country terminology comes from the Publications Office’s public authority scheme. Map geometry is Natural Earth public-domain data, simplified locally; it makes no runtime map request. Word filtering uses MIT-licensed stopword lists and app-owned parliamentary exclusions.

Production caches, activity databases, recording catalogues, user following lists and private hosting configuration are not included in the repository.

Questions in the MEP activity feed are listed once at their original document date. Answers remain linked by the exact source relationship, retain their own dates in the reader, and are excluded from MEP activity totals. Following checks the saved index for new answers to questions by followed MEPs and individually saved questions; these are labelled as answer updates.
