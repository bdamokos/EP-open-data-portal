# Public data sources

This page lists the external sources the application uses, what each provides, and the quirks a contributor needs to know. It describes current behaviour. Change history belongs in Git and pull requests.

| Source | Use | Access |
| --- | --- | --- |
| [European Parliament Open Data API v2](https://data.europarl.europa.eu/en/developer-corner/opendata-api) ([specification](https://data.europarl.europa.eu/api/v2)) | MEPs and dated rosters, memberships, questions and answers, speeches, agendas and meetings, procedures, plenary documents, adopted texts, `/external-documents` (Commission follow-up documents), vote results and decisions, corporate bodies | Anonymous JSON-LD, Atom and XML from `data.europarl.europa.eu/api/v2` |

| [Legislative Observatory (OEIL)](https://oeil.europarl.europa.eu/oeil/en/find-out-more) | Dossier stages and document summaries, English and French where supplied | Anonymous HTML parsing of exact procedure-file and document-summary pages |
| [Publications Office knowledge graph](https://op.europa.eu/en/web/cellar/cellar-data/metadata/knowledge-graph) | Legislative progress and event-linked documents, EuroVoc, country terminology, procedure-phase labels, topic timelines, cited EU acts and Commission documents; exact proposal identities and original DOCX act/annex parts | Anonymous SPARQL GET to `publications.europa.eu/webapi/rdf/sparql`, bounded RDF-tree and DOCX reads from `publications.europa.eu/resource/` |
| [Parliament Multimedia Centre](https://multimedia.europarl.europa.eu/) | Recording metadata and the official embed URL | Undocumented JSON endpoint behind the public website (see below) |
| [Parliament’s published player](https://webstreaming.europarl.europa.eu/) | Playback through the official embed, and the list of interpretation tracks | Official iframe, created only after Play; undocumented player metadata |
| [Plenary live status](https://www.europarl.europa.eu/plenary/en/home.html) | Current debate title and update time, in English | Anonymous JSON from the homepage's `getSpeakerListAndPlenaryMessages.html?dateSys=YYYYMMDD`; no page scraping |
| [European Commission EbS+](https://audiovisual.ec.europa.eu/en/ebs/grid?ebs=no&ebsplus=yes) | Current broadcast metadata and multilingual live video | Anonymous JSON and the broadcaster's official iframe; see Live plenary below |
| [EUR-Lex](https://eur-lex.europa.eu/), DOCEO, official website pages | Reader links | Outbound links only; never fetched |

Bundled supporting data: committee labels from the corporate-bodies API, country labels from the Publications Office authority scheme, Natural Earth map geometry (simplified locally), and MIT-licensed stopword lists. See [Third-party notices](../THIRD_PARTY_NOTICES.md).

Procedure labels use the 22 `ProcessType` concepts in Parliament's [procedure taxonomy](https://data.europarl.europa.eu/def/ep-procedure-types.ttl), version `20260131_1`, bundled in `server/procedure-types.mjs`; rendering makes no vocabulary request. Subtypes and grouping concepts are separate. Deprecated types keep their codes and deprecation status. Budget adoption, preparation, discharge and management share the budgetary family; legislative initiatives remain distinct from legislative procedures. Consent and historical assent retain a separate family because their code alone does not establish legislative nature. No family establishes enactment. Classification preserves supplied type declarations and canonical reference suffixes, distinguishing missing, known, unknown and conflicting types; conflicting declarations supply no selected code. A reference suffix checks supplied declarations without replacing a missing type observation.

## Access rules

- Every source is anonymous. No adapter uses credentials, private exports or copied production caches. A failed public request becomes a reported gap. It must never lead to credentials or to bypassing a protection such as DOCEO's browser verification challenge.
- Server routes are read-only. Callers cannot choose an upstream host, supply upstream query text (such as SPARQL) or make the server follow a URL. Corpus search runs user queries only against locally stored text. Endpoints are built from validated identifiers (`server/odp.mjs`, `server/source-record.mjs`, `server/legal-references.mjs`).
- Requests never forward the caller's cookies or authorization and never forge an Origin. Open Data API and portrait downloads reject redirects. OEIL and Publications Office reads follow same-origin redirects only (`server/official-context.mjs`). Downloads stream within size limits.
- The [Open Data API v2 specification](https://data.europarl.europa.eu/api/v2) publishes a maximum of 500 requests in five minutes to the same endpoint. Because endpoint scope is not defined more precisely, the application conservatively shares one rolling 500-start allowance across all API v2 endpoints, IDs, languages and query strings. Foreground reads, Atom feeds, index/corpus metadata and retries use the same allowance; coalesced readers and cache hits add no requests. The exact five-minute boundary remains counted. Background jobs may use at most 400 starts (80%), reserving 100 for visitors and other foreground readers.
- The API quota does not cover website portraits, RSS, document distributions, Multimedia Centre/player metadata, OEIL or Publications Office SPARQL. Their public references below document no equivalent numeric allowance; local concurrency and size bounds are resource safeguards, not claims about source terms. RSS, distributions, Multimedia Centre/player metadata and each official-context origin use separate admission pools (two active operations, at most one background-owned admission at a time). Portraits retain their separate bounded image pool. Source-specific 429/503 pauses honor valid `Retry-After` seconds or dates without shortening them; missing or malformed hints use a 60-second fallback (`server/upstream-queue.mjs`). No mandatory two-second delay applies to API requests.
- Use one source-cache writer, one leased activity-index writer and, when enabled, one leased corpus writer that opens the index read-only. A lost activity lease cancels its current iteration; a later normal tick must acquire ownership again before resuming the saved generation and task cursors. Explicit service shutdown remains permanent. Generation helpers renew a still-live lease after completion without reviving expired ownership or increasing its duration. Page views never start an indexer or a corpus download.
- The activity writer delegates atomic generation preparation and publication to a background thread under the same logical lease. HTTP reads keep the published WAL snapshot while pruning and copying run. The caller suspends its heartbeat writes until the thread exits; a live owner checked after `BEGIN IMMEDIATE` retains the unbroken SQLite write lock and renews the same owner before commit, using the normal 90-second duration. Expiry outside that qualified transaction still fences the old owner. Cancellation waits for thread exit and transaction rollback before releasing the caller's lease. No collector, source request or separate quota pool starts in that thread.
- Join records only by exact identifiers, never by title, tally or name similarity. Keep source URLs, retrieval times and languages. Missing observations stay null or explicit gaps, not zeroes.
- Question and document titles decode one layer of named and numeric character references as plain text. Raw source records, language keys, identifiers and provenance remain unchanged; decoded markup is displayed as escaped text. Activity previews decode retained title literals when read, without rebuilding the index.
- Caches, indexes, corpora, recording catalogues, following data and hosting configuration stay outside Git.

### Recovery ownership and quota observations

`npm run data:audit -- --reconcile` reads the configured databases without creating stores, acquiring leases or fetching sources. It reports core, amendment and group queues in both serving and working generations, durable gap classes, deferred amendment discovery, mutable-document backlog, exhausted press retries and exact question/answer files without retained text. Eligible files with no task are repair candidates; completed tasks without text require extraction/source diagnosis. Language-policy exclusions stay separate. Each database has its own snapshot, so concurrent progress can change a candidate before repair. Unavailable databases and older missing tables remain unknown. The command cannot prove that a configured worker is running or enumerate unpublished upstream data.

`ACTIVITY_INDEX_RECOVERY_MODE=backfill` wakes the existing writer for already-due durable source gaps between daily refreshes and admits at most 25 per iteration. After eight ordinary task dispatches, it reserves one dispatch for a ready canonical coverage task, alternating between admitted gap recovery and adopted-text discovery/detail work when both are ready. The turn survives iterations and restarts; an empty lane leaves ordinary work available. This bounds priority delay in dispatches, not elapsed time or requests, and leaves the separate history-readiness allowance intact. Core recovery uses a working generation and ordinary publication, preserving frozen Following snapshots and assigning recovered identities their publication marks. Successive admission batches share that working generation. It preserves saved task bodies/cursors, admission deduplication, upstream retry times and all ordinary request/time/disk limits. Gap deadlines govern the next admission; an already-admitted task retains its own execution/retry deadline. New failures return to their usual cooldown. `normal` retains priority ordering and the daily admission cap; coverage-window labels and parser/source-research gaps require their own resolution.

The gap audit also enumerates exact declared adopted-text/SP metadata relationships, retained records, missing owners and a relationship-universe digest. Legacy and unobserved roots remain outside that known denominator and are counted separately. Every audit reports this relationship inventory; `--baseline` compares missing relationship identities and their universe digest. Mutable-document metrics include the due adopted-text count/share, unknown source types and oldest due age; an empty or unknown denominator has no share.

In backfill mode, the existing writer also admits at most 100 overdue mutable documents per iteration, in oldest-due order. It excludes canonical tasks, amendment jobs, durable gaps and saved continuations that already own a retry or cursor. Further batches share the same working generation, including between daily refreshes; ordinary publication waits until these eligible admissions are drained. The cohort contains deadlines already due when that generation began; later deadlines can start the next cycle instead of extending the current one indefinitely. Request, time, disk and lease limits still apply. Upstream failures keep their existing retry/gap policy and do not prevent other eligible documents from being admitted. Normal mode retains one mutable batch per cycle and the existing weekly check interval.

Amendment-list detail uses `/documents/{id}`. List identifiers found in plenary feeds/catalogues keep that route, and ordinary legacy plenary-route retries use it when due. Exact identity, type and term are validated before retention. Discovery protects pending tasks, durable gaps and saved owners across both route keys. Amendment-list metadata creates no individual MEP activity and its periodic checks remain with the dedicated amendment collector.

Backfill mode admits a one-time correct-route verification for an exact legacy plenary-route 404, through that gap's existing owner. It scans at most 25 keys per batch and copies at most 16 KiB of saved task context per key. The old gap and its clocks stay intact during admission; the task retains the original failure history and starts attempts for the new route at zero. Pending legacy, canonical, amendment-detail and deferred owners block admission, and execution rechecks ownership. A fresh validated response must be retained before the gap closes. Correct-route failures use ordinary retries and unshortened Retry-After; the persisted task prevents repeated admission. The scan cursor resumes after restart and stays inside the normal writer, request, time and disk limits. The audit reports admission progress separately from retained recovery. Normal mode keeps its existing cadence.

The leased writer can reconcile a legacy plenary-route 404 from a strictly newer exact retained list observation. Direct detail and expanded-parent observations keep their separate basis, original URL/date, retained-source date and direct-check date. An expanded observation also needs explicit available distribution metadata. Older, conflicting, incomplete or future-dated evidence leaves the gap intact, as does any unfinished owner or admission marker. A persisted scan resumes unfinished progress across restarts, examining at most 25 keys and 8 MiB of list and canonical source bodies per batch. Batches advance between task dispatches within the existing time and disk bounds. An unfinished scan keeps the worker due even when all source retries are future; asynchronous disk checks separate those local batches. Continuation checks read owner keys and retry clocks without copying task bodies. Later successful list writes can reconcile their own identity. Reconciliation retains metadata before retiring the obsolete error and publishes through the ordinary working generation. It makes no source request and proves neither a new direct fetch nor downloaded amendment wording. Recovery admission and rerouted legacy jobs respect owners on both routes and in amendment metadata queues; waiting leaves their cursors, attempts and retry dates intact. Fresh input cannot supply the internal provenance reserved for retained projections.

Saved audit JSON can be supplied with `--baseline FILE` to compare exact gap/task/distribution identities. Reports retain a digest of the eligible question-file URL universe and distinguish newly missing entries from resolved entries. Mutable admission candidates have their own exact identities, oldest deadline and digest, excluding existing owners. Leaving that candidate set can mean queued rather than refreshed. A resolved queue entry still needs retained-data validation. Error-message classifications are diagnostic: 5xx/timeouts are transient, 404/410 record source absence at that attempt, and malformed archives/unsupported content remain source-or-parser problems. No class alone proves that a record will never be published.

There is no comprehensive background backfill for these readers; indexed sitting outcomes and retained corpus text cover only their documented subsets. |

`[odp-monitor]` summaries retain at most 60 UTC-minute buckets in memory and expose the latest five buckets, status counts, route families, successful header latency, failed header-wait duration, local allowance and pacing. Failed fetches distinguish local reader deadlines/cancellation, transport timeouts, DNS, connection, TLS and unclassified aborts/errors using fixed labels and allowlisted runtime codes. Up to 16 pending header waits expose only route family and elapsed time; request-deadline logs include the same bounded header snapshot. Failure counters describe rejection before response headers, not body consumption or upstream quota scope. `[odp-throttle]` records 429/503 observations, parsed server pauses and allowlisted numeric quota hints. HTTP 503 is a capacity/error observation, not proof of a quota. These ODP diagnostics contain no request identifiers, query strings, error messages, response bodies, cookies or credentials. Existing service logging supplies persistence; the in-memory window resets on restart. Modes `backfill` and `steady` smooth starts at 750 ms and 1500 ms respectively, increase spacing on 429/503 and recover gradually after successful responses. The default `normal` preserves existing pacing. None raises the shared rolling allowance or shortens server pauses. Comparing useful request starts and observed throttles measures an operating envelope, not a contractual quota; other processes sharing an upstream IP are outside the process-local counter.

`server/public-data-policy.test.mjs` and `server/public-serving.test.mjs` enforce the routing and configuration boundary.

To add a source, document it here (access path, licence, limits), route it through the existing client, cache and queue, and add a small test fixture that records its source URL and retrieval time.

### Character references

The handwritten text decoders share `server/character-references.mjs`. Each adapter selects its existing policy; all require semicolons and decode one layer per call. Decoded markup remains text and still needs output escaping. Raw records, identifiers, language keys and provenance are unchanged.

| Adapter | Named references | Numeric references and invalid input |
| --- | --- | --- |
| `source-titles.mjs` | Case-sensitive `@nodable/entities` `ALL_ENTITIES` table | Decimal and `x`/`X` hexadecimal; preserve zero, surrogates and values above U+10FFFF. Non-string values pass through. |
| `member-votes-model.mjs` reference text | Five XML names, case-sensitive | Decimal and lowercase `x` hexadecimal; preserve zero, surrogates, values above U+10FFFF, C0 controls except tab/LF/CR, and U+FFFE/U+FFFF. |
| `press-releases-model.mjs` `decodeHtml` | Case-insensitive XML names plus `nbsp`, curly quotes, dashes and ellipsis; `nbsp` becomes an ordinary space | At most seven decimal or six hexadecimal digits (`x`/`X`); preserve zero and values above U+10FFFF. Existing surrogate/control decoding and string coercion are retained. |
| `amendment-splits.mjs` descriptions | Five XML names, case-sensitive | Decimal and `x`/`X` hexadecimal; unsupported references produce `unsafe_xml`, invalid numeric values or C0 controls except tab/LF/CR produce `invalid_xml`. Existing U+FFFE/U+FFFF decoding is retained. |

Unknown or malformed references stay literal except in split descriptions, whose XML checks reject them. Split descriptions unwrap a fully escaped `partValue` fragment at its boundary, then decode text nodes once; CDATA stays literal. XML validation still applies before text decoding, including rejection of uppercase `#X` in an ordinary fragment. Press feeds retain their XML-parser layer followed by their title-text layer. Tag removal and whitespace handling remain in the adapters.

Other XML readers use `fast-xml-parser`; OEIL enables its HTML entity mode. `src/Transcript.tsx` uses the browser's XML `DOMParser`. Those parsers own tree, attribute and CDATA handling and do not add a second shared-helper pass. There is no handwritten character-reference decoder in `src`; its following-store `decode` functions read JSON.

## Source notes

### Current member directory

Member lists sort by the displayed full surname (including particles such as “del”), then given name, using fixed English collation with accents significant and case ignored. Numeric member ID breaks ties. The EP `sortLabel` is retained as source metadata but is not an ordering key: it can concatenate surname and first initial without a separator. The Members wall, its country/group/committee filters and the amendment author picker share this ordering; Following keeps its saved-item order.

The directory exposes the current roster and exact committee catalogue identifiers before optional detail reads finish. Retained multilingual names and source freshness remain available; missing names fall back to exact committee codes. Committee filters show known members with explicit incomplete coverage until all current profiles are available. Membership retries read missing profile IDs only.

Profile organisation names link to the current Members list using exact temporal EP body IDs. Committee, delegation, political-group, national-party and working/governing-body links clear unrelated facets; ordinary committee controls remain available to narrow results. Dates are evaluated inclusively on the directory's Brussels day. Missing or invalid dates never establish current membership. Ended bodies are not expanded to successors, and canonical families or similar names do not broaden the filter. The directory reuses already loaded public MEP membership observations without extra body requests; missing or malformed observations and uncertain dates preserve incomplete coverage independently of known matches. Exact body bounds already observed through the source cache suppress memberships of ended or future bodies without adding requests. The optional URL organisation name is display text only; only the organisation ID selects members.

Public corporate-body records (`/corporate-bodies/{id}`) provide multilingual preferred/short names, classification, temporal bounds and, where supplied, stable `isVersionOf` relationships or represented countries. These fields establish identity and naming, not a prose description or remit. No Wikipedia or Wikidata enrichment is acquired by this adapter.

Profile `countryCode` and `groupCode` come from `/meps/show-current`, joined only by exact `identifier`. The per-MEP record supplies country authority URIs on mandate memberships and political-group organization IDs, rather than these roster codes; citizenship is not country of representation. `currentAffiliation` records the Brussels observation day, person ID, match status, roster source URLs, retrieval dates and stale markers. It describes the current roster, never historical membership. Missing codes, non-current members and unavailable or ambiguous roster matches return `null`, with match status and errors distinguishing these cases. Roster failure preserves the rest of the profile and is uncacheable at the response layer.

The `hasEmail` flag describes a non-empty email in the source record: omitted contact data is `null` (unknown), an explicit empty value is `false`, and a supplied email is `true`. The directory initially has roster evidence only; once an exact-ID profile is loaded, its email flag enriches the directory too. Thus a partially loaded directory can report unknown while a profile reports true. `hasCv`, `hasNews` and `hasVideo` are `null`: these capabilities are not established by this adapter. None of these flags infer absence from an omitted property.

Current-member profiles show role periods for their active committees. Profiles without a current-roster match retain readable open committee records under “Committee records”, with omitted end dates explicit and no current-role claim. The MEP API supplies each role and its dates; corporate-body `isVersionOf` relationships connect temporal versions of the same committee, including midterm reconstitutions. Matching names or abbreviations never establish continuity. Consecutive, non-overlapping periods of the same role and classification are combined for display; role changes, gaps, unknown dates and conflicting roles remain separate. Original membership IDs, body IDs, periods and source retrieval dates remain in the profile response. Older periods can span legislative terms; their dates describe service in that committee, not a new appointment inferred from a midterm boundary.

Profile-only enrichment shares one eight-second optional deadline across affiliation/role labels and committee history, using the existing source cache and queue with at most two reads at once. Political affiliations take priority, then valid start dates from newest to oldest, including open periods, with at most 16 additional exact corporate-body network reads. Up to 100 bodies can supply labels from retained records, including the profile's batch request, so older delegations beyond the network budget keep their names. Committee history retains its 64-body bound. Missing, stale or mismatched labels preserve readable rows and successful profile fields, with retry through the profile reader. Retrying refreshes rejected member observations and bodies within the network budget while reusing valid cached records; a failed refresh preserves readable data. Directory and feed indexing do not perform these body lookups.

Two collapsed sections show political affiliations, delegations and other roles, including governing and working bodies and Parliament-level offices held as President, Vice-President or Quaestor. They retain individual membership, body, role, classification and date observations, including language maps, body relationships, source URLs, retrieval dates and freshness. Labels require an exact body identity and classification match. For display, consecutive, non-overlapping periods with the same role and classification combine only for the same body ID or an explicit canonical `isVersionOf` identity. National-party display periods also combine across a parliamentary-term boundary when the source bodies meet at that boundary and their country, non-placeholder party code and complete language-name maps match exactly. Missing or stale metadata, changed names or codes, conflicting canonical identities and ambiguous observations keep periods separate. This display fallback supplies no canonical identity; original records remain separate in the profile response. Missing membership observations differ from a verified empty list. Malformed or incomplete observations remain in the raw data with explicit coverage issues; supported rows remain readable. Label completeness is separate from observation coverage and date issues. Missing or invalid dates remain uncertain. An omitted end reads “Present” only for a dated membership begun in the current term and current service, with a current-roster match and no ended body; a combined display period retains that terminal record’s status. Dated national-party and political-group records do not establish current affiliation. Records with valid bounded periods sort latest first, followed by uncertain periods.

The profile’s “MEP since” date requires an exact current-roster match and comes from explicit `MEMBER_PARLIAMENT` memberships of `org/ep-N` bodies in the same MEP record. Consecutive mandate periods combine into continuous service across parliamentary terms. A gap starts a new spell; earlier service is displayed separately. Profiles outside the current roster remain accessible and show retained periods under “Parliamentary service”, including explicit missing end dates; roster absence never supplies a departure date. Committee roles, party memberships and the current term’s opening date never substitute for missing mandate dates. The response retains the source mandate IDs and dates; ambiguous or invalid observations remain explicit gaps.

### Reading a document in context

Whole comparison-cell notes that explicitly exclude the selected language edition are preserved as published and shown as “No change in this language version”. They supply no replacement or deletion and are never placed over legal wording. Recognition uses verified language-specific wording, including published paragraph prefixes, repeated numbered notes and printed underscore dividers. Every substantive line must be a same-language note; changed footnotes prevent whole-column recognition. A standalone verified note alongside other wording returns an unresolved mixed-scope result with exact note offsets in its source field. Both published columns remain visible without replacement/deletion highlighting. Matching-language legal text remains readable, but automatic placement is withheld because flattened columns do not establish a safe per-footnote splice. Empty cells and source wording remain as published. Other editions are evaluated separately. Unrecognised notes retain their original text.

Amendment readers show a published justification beneath the comparison for its source version and language, preserving paragraph breaks. Missing or blank justifications have no section. Retained text from another edition is withheld.

The on-demand `final-text=1` context read pins an amendment, published list and wording language. It grounds the original column in the same dossier's Commission proposal, then compares complete provisions against an explicitly linked Parliament adopted text. A resolution-only publication can identify an original final EU act through its explicit English correspondence statement and verified CELLAR procedure, institution and language relationships. Parliament and final-act observations remain separate. An exact complete-provision match reports the same wording; a mapped provision with rewritten wording reports different wording. A shared phrase alone does not establish that an edit was retained. Wording matches do not supply an individual vote result or official amendment lineage. Referenced notes must be verified as part of the selected passage; comparisons with unverified amendment, baseline or destination notes remain unavailable. Missing bodies, competing editions, unsupported operations and ambiguous provision mappings remain unavailable. Reads share the existing source budgets, start no collector and retain source hashes; the public reader names the compared publication and shows its published wording.

The lazy context reader uses the exact `/plenary-documents`, `/documents`, `/procedures` and `/adopted-texts` records and their declared DOCX files. Croatian committee lists also retain exact `Amandman` number boundaries and target lines marked by effective bold formatting when template paragraph styles are absent. Published French, Hungarian and Romanian committee-list class lines are retained as document metadata; the following legal address and underlying-act references stay separate. It can read one amendment from at most four explicitly linked published lists when indexed wording is missing; list-number ranges select candidates, while the actual parsed individual number establishes inclusion. An explicit `wording-lang` selects a source language within an exact amendment and list. When that language has no document text publication, the reader can extract the same amendment number from another declared language edition of that same list. Matching languages prefer the requested language, English, the document's original language, then the documented display order. It downloads only the selected edition and preserves its wording, label and source language; the reader shows the actual text language. `unknown` selects a null source language and cannot establish the body's language. Conflicting or unreadable same-language files withhold matching. This read does not alter the index or resolve published proposer names into member identities. On-demand adopted-text discovery requires an exact procedure link and reciprocal `adopts`, independently of the original text's recorded outcome. When the index already retains an exact term-10 adopted work with an explicit `adopts` edge to the requested document, the reader returns that choice from one bounded read snapshot without repeating source requests. Retained choices stay partial; they do not establish a complete list. Opening that exact adopted text can also reuse its retained metadata when it observes exactly one supported DOCX declaration for the requested language. Report and motion amendment contexts can use the same retained-metadata path when the index already supplies the exact requested amendment and selected list. They also require a verified term-10 root and exactly one supported DOCX declaration for the requested body language. Selections that may switch the body language keep ordinary metadata discovery. Unknown, missing, unsupported or competing selected-edition declarations use ordinary metadata retrieval so later publications can recover. The existing DOCX reader loads the selected declared edition. If that retained body is unavailable or errors, one ordinary metadata read can recover a replacement; the body is retried only when its selected-edition declaration or source version changes. Unchanged failed declarations are not downloaded twice, and local cancellation/budget failures retain their errors. Sources identify the retained index projection, generation, epoch, original retrieval time and projection hash, with stale status and any retained refresh error; these responses receive no fresh computed TTL. Missing or invalid retained relationships use ordinary on-demand discovery. No read enqueues work or selects a held source preference.

Document readers display bounded embedded PNG, JPEG, GIF, WebP and BMP pictures through their owning DOCX part relationships, retaining source object offsets, media hashes and published descriptions. Images in notes and table cells keep their source positions and bounded published display extents. Hidden and deleted compatibility pictures follow the shared visibility rules; repeated placements share one inflated media part. Supported compatibility pictures select one representation. External pictures, unsupported transforms, vector formats and grouped drawings remain explicit; rendering does not establish complete or comparable legal wording. Image extraction retains at most 100 pictures, 4 MiB per part, 12 MiB total inflated media and 20 million pixels per image. Verified image bytes travel once per document in a deduplicated, MIME-validated registry. Public JSON contains only descriptors. `GET /api/document-image/{source-sha256}/{image-sha256}` serves previously extracted, hash-verified bytes without fetching caller-supplied URLs, within 32 MiB of memory and a separate 64 MiB disk cache (200/1,000 entries). Eviction or cache failure leaves text readable with an unavailable image; the document-text and proposal parsing memory caches each account for retained image data within a 64 MiB budget.

`GET /api/document-pages/{document-id}?lang=…` reads only a uniquely declared PDF of that exact public work and language, including explicitly linked question answers. It accepts no caller-supplied download URL. Redirect hosts and response bytes are bounded, PDF signatures are checked, and a 32 MiB process cache retains at most eight reads for one minute. ### Documents (DOCX)

Distributions linked by the API are processed locally with bounded decompression (`server/document-text.mjs`): at most 8 MiB downloaded and 12 MiB aggregate inflated XML across the selected parts. Extraction reads `word/document.xml` plus style, numbering, settings, footnote and endnote parts. It omits deleted/moved-from text and effective `w:vanish` or `w:webHidden`, including inherited/default styles and direct overrides; inserted/moved-to text remains visible. Automatic numbering, referenced notes, links and literal braces/angles are retained. The shared reader and amendment extractor continue counters across concrete instances of the same abstract list; explicit start overrides restart a level on first use. Level restarts follow [Word's documented rules](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/140a2cd9-2f26-456d-9760-ae6ecef4e8b5), including higher-level triggers. Literal paragraph labels remain unchanged. Page-dependent note restarts and unsupported numbering are explicit gaps. Question and answer text readers can use the API-declared PDF fallback described below.

An omitted API distribution is distinct from an unpublished DOCX. For example, B-10-2026-0435 and B-10-2026-0436 have public English DOCX files in Parliament's `reds_iPlRe` distribution, while their `/plenary-documents` and `/documents` records omit `is_realized_by`. The reader requires declared distributions and keeps these records unavailable; it neither constructs fallback file URLs nor extracts PDF/HTML text.

Known `w:sym` font/code pairs are converted mechanically: Symbol `F02D`/`002D` becomes U+2212 MINUS SIGN using the [Adobe Symbol mapping](https://www.unicode.org/Public/MAPPINGS/VENDORS/ADOBE/symbol.txt) and [Microsoft's legacy symbol-font offset](https://learn.microsoft.com/en-us/typography/opentype/spec/recom#non-standard-symbol-fonts). Other symbols, drawings, equations and unsupported inline objects retain an object replacement character (U+FFFC), source position and metadata without discarding surrounding text. Their paragraphs have `complete:false`; a leading known symbol does not make its paragraph incomplete.

`paragraphs` remains a string array. `paragraphSources` aligns with it and supplies indexed XML `path`, zero-based source paragraph `ordinal`, `container`/`containerPath`, continuity `segment` and `complete`. Matching across paragraphs requires complete text, the same container and segment, and consecutive ordinals. Omitted paragraphs, unsupported blocks, tables and cell transitions interrupt continuity. When skipped content may consume list items or note references, later affected automatic labels are `?` with a warning and incomplete paragraph metadata. `documentObjects` locates mapped/unresolved objects by paragraph and UTF-16 offset. `structureStatus:not-extracted` means boundaries are unknown; legacy records never receive inferred structure. Reader responses also expose `extractionVersion` and `sourceVersion` (the API listing's `byteSize` and `issued`, distinct from downloaded byte length).

English term-10 adopted-text readers separate a recognised masthead and repeated short title from the formal resolution heading and body. Recognition requires the Parliament/term masthead, TEXTS ADOPTED, the exact `P10_TA(year)number` reference and the shared resolution-body boundary. A drawing at the masthead’s standalone logo position, between the term and TEXTS ADOPTED, is omitted from presentation; its extraction record remains unchanged. Only the corresponding object warning is suppressed, with valid source/object positions and complete visible text and notes. Other missing content and unknown structure retain the original-document notice. The context reader also flags unannotated object replacement characters in paragraph or note text when object metadata is absent. Unrecognised covers and other languages remain unchanged.

Presentation is recorded beside the unchanged text (`server/docx-formatting.mjs`). `paragraphFormats` aligns with `paragraphs` and gives alignment, left/hanging/first-line indents in em at the body text size, heading level from `w:outlineLvl`, a relative size class, and bold, italic, underline, strike, superscript and subscript spans as UTF-16 offsets; style inheritance follows `basedOn`, toggles combine across paragraph and character styles, and direct run properties win. `tables` lays out outermost tables as exact paragraph ranges per cell, with grid spans, vertical merges and whether any cell keeps visible borders; nested tables stay inside their cell. `formatStatus:not-extracted` means presentation is unknown and readers show plain paragraphs. Texts saved before formatting was recorded remain readable and are re-read in the background when opened.

Extracted texts are saved in `ODP_CACHE_DIR/document-text-v1` with source URL, retrieval time, extraction version and the API's file size and issue time. An older extraction version is replaced only when the document is opened; a failed upgrade retains the disk record and reports text unavailable under the current parser. Cold reads propagate typed local admission/deadline failures so API callers can return retryable errors; a failed background refresh still serves retained text. Distributions send no HTTP validators, so the API listing is the change signal: a different size or issue time re-reads the file. Otherwise a text retrieved within 60 days of its document date is re-read at most weekly when viewed, and a text retrieved later is kept. The directory is capped by `DOCUMENT_TEXT_MAX_DISK_MIB` (default 256) and removes the least recently read texts first; a removed text is downloaded again when next opened.

Proposal parsing reuses bounded DOCX extraction and adds ordered provision paths, replacement scopes, structured table cells and safe MathML objects. It retains memorandum and financial-statement content separately from the legal body, supports all 24 official-language label grammars, and keeps unsupported objects and duplicate targets explicit. The proposal-only numbering resolver continues shared abstract lists with explicit restart overrides; the general document reader keeps its existing default. See [Proposal structure](PROPOSAL_STRUCTURE.md) for the interface, matching policy, completeness and cache rules. This parser does not fetch or select proposal baselines. The Publications Office’s [French drafting rules](https://style-guide.europa.eu/fr/content/-/isg/topic?identifier=3.3.2-additions-and-numbering) and [Latin-numbering inventory](https://style-guide.europa.eu/fr/content/-/isg/topic?identifier=annex-b-use-of-italics) define extended and compound suffixes; attributed Council and Parliament labels in `server/fixtures/legal-latin-numbering.json` verify their use. These public guides inform deterministic grammar rules and do not identify a baseline or authorize cross-language joins. The Commission’s [DGT English Style Guide, Annex 3](https://commission.europa.eu/system/files/2023-11/styleguide_english_dgt_en.pdf), documents three-letter Greek serial labels; `server/fixtures/greek-serial-points.json` retains the numbering inventory and a Greek Regulation 1217/2010 excerpt.

### Press releases

The activity-index writer reads Parliament's English RSS feeds for [press releases](https://www.europarl.europa.eu/rss/doc/press-releases/en.xml), [plenary](https://www.europarl.europa.eu/rss/doc/press-releases-plenary/en.xml) and [committee](https://www.europarl.europa.eu/rss/doc/press-releases-committees/en.xml) press releases once a day (`server/press-releases.mjs`, `server/press-releases-model.mjs`). Changed publication dates, GUIDs, links or titles, and reappearances after an observed absence, reopen failed releases. Unchanged feed items preserve failure history and retry deadlines. Each feed holds only its latest 20 releases and carries no procedure or document references. Coverage therefore starts when following starts, and releases that leave the feeds between reads are missing. Following data accumulates in `press-v1.sqlite` in the index directory and is not rebuilt with index generations.

Releases are discovered only through these feeds. Each announced release's English page is read once; press-room listings and search are never crawled, and links on a page are never followed. Parliament's robots.txt does not disallow `/rss/` or `/news/`. Only exact links in the page's own “Further information” list count: OEIL `procedure-file?reference=…` (encoded slashes and stray spaces are normalized), OEIL `document-summary?id=…`, and Doceo reports, motions, adopted texts and committee drafts (`A`, `B`, `RC`, `TA`, `PR`, `AD`, `AM`, `AL`, `PA`). Minutes, agendas and verbatim reports cover many files and are ignored. A summary or document link matches a dossier only when that dossier's OEIL procedure file links the same ID. Links in body text are context mentions. Titles, committees and topics never establish a link. Pages whose robots meta tags or `X-Robots-Tag` header say `noindex`, `nofollow` or `none` are neither shown nor used. Reads use the website admission pool, the browser-compatible user agent and the worker's request budget and deadline: at most six pages per worker iteration, 2 MiB per page. While index work is also due, press reads take a tenth of the budget, or one request every other iteration when the budget is below ten; this alternation resets when the worker restarts. Each feed's releases and status commit together, so an interrupted poll resumes with the remaining feeds. Writes hold the activity-index lease until they commit; readers never create the store.

The committee “latest news” feed is not followed: its highlight pages carry `noindex, nofollow` and no procedure or document links. Plenary newsletter items have no feed of their own.

`GET /api/insights/press-releases?reference=…&lang=…` returns the latest five matching releases with English titles and source URLs, the total found, and coverage: the following start, each feed's last success and error, whether the procedure file's summaries and documents could be checked, and whether that saved page is stale or failing to refresh, and counts of pending, unreadable and unlisted releases. `complete` is always false. The dossier reader shows up to three releases under agenda items and five in the Dossiers view, and nothing when none were found.

Placement requires unique original wording in the addressed provision, preserving words, numbers, labels and internal punctuation. The outer amending instruction and inner replacement remain separate; a partial quotation cannot establish a whole-article replacement. The reader labels this baseline “Existing act” and links its dated consolidation. Consolidations are documentation texts, as described in the [EUR-Lex consolidation guide](https://eur-lex.europa.eu/collection/eu-law/consleg.html?locale=en).

CELLAR uses `application/rdf+xml;notice=tree` for metadata and `application/vnd.openxmlformats-officedocument.wordprocessingml.document.main+xml` for DOCX. A bounded406 XML error on the selected DOCX item may explicitly advertise `application/zip;type=akn4eu`. Only that declared type permits one same-item retry; the response must match that MIME parameter and validate as a bounded Word OPC package, including its main content type, internal document relationship and Word document namespace. This is DOCX transport compatibility, not an AKN reader. Declared manifestation format, accepted HTTP type, response Content-Type and the hashed406 advertisement remain separate provenance. Representation validators are never carried from the rejected type to the negotiated type. No negotiation follows multipart, throttling or unrelated errors. Upstream HTML is never served. Only validated `publications.europa.eu/resource/celex/…` and discovered CELLAR UUID paths are fetched. At most three same-host redirects are followed, upgrading validated HTTP Locations to HTTPS. Each operation uses the shared Publications Office origin queue and a 20-second admission/redirect/body deadline; one baseline read has a 45-second owner budget. Metadata is capped at 3 MiB, DOCX/XHTML at 8 MiB per part (the existing reader limit), 24 MiB per bundle and 32 parts. Source throttling uses the origin queue's Retry-After pause.

Metadata expires after six hours. Viewed content is conditionally revalidated after seven days with ETag/Last-Modified. A SHA-256 blob cache outside Git (`ODP_CACHE_DIR/commission-proposals-v1`) has a 256 MiB disk budget and 24 MiB memory budget; identity/language/item/format records retain validators and retrieval/check dates. Failed or malformed refreshes retain the last valid source with stale/error gaps. A valid partial source is never labelled complete. Content hashes and exact RDF identifiers are returned for downstream parsing and mapping.

Proposal text retains the Commission/Publications Office source, language, version and original-file URL. Reuse follows the [EUR-Lex legal notice](https://eur-lex.europa.eu/content/legal-notice/legal-notice.html?locale=en) and document-specific third-party exceptions; Cellar metadata is CC0 under its [legal notice](https://op.europa.eu/en/web/cellar/legal-notice). Any derived diff must identify its modifications and must not be presented as an official consolidated text.

- Procedure progress loads independently from summary text through `/api/insights/procedure-progress?reference=…&lang=…`; `detail=documents` is requested only after a reader opens an event's documents. Exact procedure references, including split suffixes, map to a single Cellar dossier. A verified unmatched mapping or a mapped dossier without events can fall back to OEIL’s exact procedure status and key events; ambiguous mappings retain their gap. The response keeps both sources, retrieval dates and the Cellar mapping state. OEIL events do not acquire Cellar document links or replace Following’s Cellar event-identity baseline. Unavailable fallback reads retain their error and retry time. Up to 300 distinct event identifiers are retained, within 1,201 event rows or 2,401 document rows; caps, malformed rows and missing/conflicting event fields remain explicit. Scheduled events stay scheduled after their date passes; future dates with no supplied status are not treated as completed actions. Council events never alter Parliament activity counts.
- Progress reuses the single official-source client, per-origin admission queue and bounded memory/disk cache. Responses are validated before caching; malformed refreshes retain the last valid observation. Viewed progress expires after one hour and refreshes in the background; saved records retain their source retrieval date and refresh errors. The browser follows an admitted background refresh with at most six increasing-delay reads within a 30-second lifecycle; failures, admission pauses and cancellation settle it while retaining the selected last-good content. Explicit retry starts a new bounded lifecycle. Stale or failed progress envelopes bypass the normal browser data cache. Saved document details use the same refresh lifecycle and can be checked again or refreshed by reopening their disclosure. There is no preload or additional writer. Source requests have a 20-second deadline, same-origin HTTPS redirects and a 3 MiB JSON limit. Fresh, complete progress responses have browser `max-age=0` and a five-minute CDN lifetime; partial, ambiguous, stale or failed responses are not publicly cached.
- Event-linked document works resolve only through exact CELEX identifiers. Reader links open EUR-Lex text using the available title language with an explicit fallback. Capped document responses retain metadata but withhold links because identifiers may be incomplete. Council metadata aliases do not establish a publicly available PDF; unsupported or conflicting identifiers do not create links. Raw graph/query URLs and Cellar resource identifiers remain in response provenance, not reader links; the existing site footer supplies general attribution. No legal-effect graph or generic entry-into-force date is inferred from these events.
- Legal references in questions and answers (CELEX, ELI, Cellar, COM/SWD/JOIN, procedure and question numbers) become lookup keys through fixed patterns and are resolved in batched SPARQL. A reference links only when exactly one work matches. Official Journal position links (`uri=uriserv:OJ…`) are not resolved.
- `src/terms.json` holds procedure-phase labels (RDG1, RDG2) in all 24 languages, with concept URIs and query provenance. IATE entries corroborate them but are not substituted.
- **Vote**, **Amendment** and some short interface labels are app-owned machine translations with model/date provenance. They are not official translations. EuroVoc 4750 (electoral voting) gives the wrong sense for parliamentary votes.

### Live plenary

`GET /api/plenary-live` reads the current Brussels day's [plenary JSON feed](https://www.europarl.europa.eu/plenary/en/getSpeakerListAndPlenaryMessages.html?dateSys=20261020), Open Data `/meetings/{sitting-id}/foreseen-activities`, and the [EbS+ current-programme JSON](https://8hwk2cyeyb.execute-api.eu-west-1.amazonaws.com/parrotfish-prod/ebs/live/EBSPLUS). These are anonymous machine reads: there is no HTML-page scraping, catalogue crawl, daily manual mapping or hardcoded event URL. The two website JSON interfaces are undocumented and have no published availability guarantee. Failures remain separate source gaps. Requests share the existing admission queues, with a 512 KiB body bound, eight-second website deadlines, a twelve-second shared owner and a thirty-second memory snapshot. Browsers poll while visible, or while the player is open, never cache the response at the CDN, and expire status after 75 seconds without a successful observation.

The plenary feed's `D…` debate IDs are a different namespace from Open Data's `…OJ-ITM-D-…` IDs. The current debate is displayed with its source title and source update time; no title-based join is made. Only today's source updates within three minutes qualify. Agenda markers say **Scheduled now** and require one timed `MEETING_PART` with one exact agenda child. Several children, overlapping blocks or conflicting end times retain ambiguity. Timetables never prove that an item is actually being debated, and missing live observations do not prove a recess or an ended sitting.

EbS+ playback uses the broadcaster's generated embed `https://audiovisual.ec.europa.eu/embed/ebsplus?language=EN`. Programme selection requires `PUBLISHED`, `LIVE`, the exact EbS+ channel ID `6082c9bb97ad8b2acf7fcc98`, today's started programme, English audio, published unlocked material attributed to European Parliament institution `2618`, and the broadcaster's explicit first title paragraph `EP Plenary Session`. This is a documented programme classification, not an agenda join. Other EP coverage, recorded footage and unknown classifications do not expose a plenary player. The metadata timestamp is an editorial update, not a heartbeat. Playback may lag the source's current-debate indication; users can use the player’s Live control. The iframe is created after Watch and remains mounted while browsing or minimising; closing it, a fresh observation without a live plenary programme, or two further minutes without any observation removes it. That grace covers background tabs, whose timers browsers throttle to about once a minute; the banner and agenda markers still expire at 75 seconds. Pop out opens the same allowlisted embed in its own window, without an opener reference to the explorer, and closes the inline player; a blocked popup leaves the inline player in place; that window is the broadcaster's page and no longer follows our status checks. The player also links to the [EP Multimedia Centre](https://multimedia.europarl.europa.eu/en/webstreaming) live listing. Interpretation controls belong to the official player. Use follows the [Audiovisual Service conditions](https://audiovisual.ec.europa.eu/en/conditions-of-use); attribution is shown beside playback. No video is downloaded or proxied.

### Multimedia Centre and player

Videos play in the Parliament's own embedded player. The Multimedia Centre website offers embed URLs for its recordings, and we use the same official embed (`https://webstreaming.europarl.europa.eu/ep/embed/embed.html?event={recording-id}`). The only difference is that we look the URL up programmatically instead of copying it from the website (`server/mmc.mjs`):

1. The recording's metadata, including that embed URL and the recording's start and end times, comes from `https://api.multimedia.europarl.europa.eu/o/epmp-frontend-rest/v1.0/media/{recording-id}`, the endpoint the Multimedia Centre website itself calls.
2. A speech's start and end times from the Open Data API select exactly one recording. The embed URL gets the player's own `start`, `end`, `language` and `audio` parameters, so it opens at that speech.
3. Before playback, the player's metadata connection confirms that the requested interpretation track exists: `wss://websockets.services.eup.glcloud.eu/content-manager/api/v1/socket.io/?EIO=4&transport=websocket`, namespace `/content`, event `join:event`, with the recording's public `commonId` (`server/player-content.mjs`). Only `PUBLISHED` content matching the recording is accepted. The embed receives the requested `audio` language and `autoplay=true`. The official player owns audio selection, loading, playback and browser autoplay restrictions; users can press Play or change audio in its controls. The parent does not poll tracks, switch channels or wait for adaptation events before showing it. Track metadata establishes availability, not proof of the audio currently playing.

Recording discovery uses the public website's JSON search, `https://api.multimedia.europarl.europa.eu/o/epmp-frontend-rest/v1.0/search?type=105&subtype=2&df={date}&dt={date}&pagesize=100&page={page}`. This interface and the metadata/player endpoints are undocumented and may change. The search's exact `mediaBusinessID`, `EventDateStart`, `EventDateEnd`, `statusName` and plenary category identify candidates; titles and ID naming patterns are not join keys. Precise speech coverage still comes from each recording's detail response.

Speech playback requests automatically load the catalogue for that sitting date. Up to ten pages and 1,000 records are accepted, with a 2 MiB limit per response. Pagination, total counts, dates, types and unique IDs must agree before a snapshot is saved. A successful first-page empty array with all pagination fields absent is the source's empty-result format; partially missing pagination or an unpaginated response later in a page walk remains an error. Concurrent readers share one search. Successful date snapshots refresh after six hours, or one hour when no recorded candidate is present. Refreshes run when the date is requested; there is no whole-term crawl or idle timer. `ODP_CACHE_DIR/mmc/catalogue-dates-v1` retains date snapshots outside Git, including exact source URLs, page retrieval times and normalized JSON hashes. The older `catalogue-v1.json` remains an untouched fallback for dates with saved recordings. Failed refreshes retain usable observations with stale/error provenance and prevent shared response caching.

Searches use the conventional `Mozilla/5.0 (compatible; EP-OpenData-Explorer/0.1; recording catalogue)` user-agent, retaining the application's identity and purpose. The plain product-only user-agent can receive HTTP 403. No credentials, cookies or forged Origin are sent. The [Multimedia API robots policy](https://api.multimedia.europarl.europa.eu/robots.txt) disallows crawling outside `/documents/`; the adapter performs date-scoped reads when playback is requested. Denied searches remain unavailable, rather than empty results; a source denial pauses further searches for one hour. HTTP 429/503 also honor the source's longer Retry-After. No browser challenge bypass, authenticated source, video download or video proxy is used. Successful server access does not establish a supported API contract; these public website interfaces remain undocumented dependencies.

### Portraits

The API supplies portrait URLs. Each MEP record's `img` field points to the website image, e.g. `https://www.europarl.europa.eu/mepphoto/4465.jpg`. The images themselves are hosted on the website, not served by the API. If `img` is missing, the same URL pattern is built from the MEP ID. Only that path pattern is accepted. Images are fetched on demand through `/api/portrait/{id}` and cached in `ODP_CACHE_DIR/portraits-v1` with source URL, retrieval time, checksum and the host's `ETag`/`Last-Modified` validators (`server/portrait-cache.mjs`). Portrait downloads and saved-image reads accept JPEG bodies up to 8 MiB; retained memory stays capped at 8 MiB and disk storage at 1.4 GB (1,400,000,000 bytes), with bounded entry counts. The roster is never prefetched. A portrait viewed more than 7 days after retrieval is refreshed in the background with a conditional request; a `304 Not Modified` keeps the saved image and records the confirmation as the new retrieval time. The Open Data API and the other periodically read sources (activity RSS, Multimedia Centre, OEIL, Publications Office SPARQL) send no validators, so they are re-read on their cache lifetimes.

Portrait version `v=2` serves an app-generated WebP within 480 × 640 pixels, preserving the original aspect ratio and never enlarging it. Original JPEGs remain unchanged; `v=1`, unversioned and JSON-API-versioned requests retain the original response. Retained reads open and validate only the requested file; disk inventory and pruning run alongside reads, and every write waits for that inventory. Derived bytes have their own checksum-based HTTP `ETag` and retain the source's freshness deadline. The derivative cache is memory-only, capped at 16 MiB and 1,024 entries, keyed by the original SHA-256 and transform version. Conversion is asynchronous and sequential, admitting at most 32 pending originals and 32 MiB of input, with a 25-megapixel decoding limit and a three-second processing timeout (`server/portrait-renditions.mjs`). The first eight roster photos load eagerly; subsequent photos use native lazy loading. Names remain usable during photo loading or failure.

## Parliament search

`GET /api/insights/search` searches current roster names and retained name variants, question identifiers and multilingual titles in the serving activity index, and retained plenary agenda titles. Agenda reads use the existing public meetings catalogue and exact `was_scheduled_in → MEETING_PART.consists_of` relationships through the cache-only Open Data reader. Conflicting repeated agenda identities are withheld, including topics whose scheduling container conflicts. Identical repeats retain the first observation’s title and source together. Search makes no upstream requests, starts no collector and creates no additional index. Each result retains its exact identity, language, source URL and retrieval date. Agenda links retain both the sitting and topic identifiers.

Result types and inclusive publication/sitting dates can be filtered. Dates do not restrict MEP names. Words are accent-insensitive; quoted phrases stay together. Titles match in any supplied language and display in the interface language with the usual fallback. Each type has ten results per page, up to offset 1,000. Question reads stream up to the newest 50,000 retained metadata rows through the existing date index; only titles are projected and matching results are bounded in memory. Agendas cover at most 500 sittings with two retained pages per sitting; caps remain explicit in coverage. Known missing agendas, conflicting records and actual scan caps are reported separately; unavailable calendars or entirely missing selected agendas remain unavailable. Names, question titles and agenda titles load independently, so a slow or failed agenda read does not hide other matches. Retained agendas can be stale. Document-text search runs separately against the corpus and retains its own language, coverage and pagination.

## Full-text corpus

With `CORPUS_ENABLED=true`, a leased worker stores current-term texts in `corpus-v1.sqlite` (`server/corpus-worker.mjs`, `server/corpus-store.mjs`). Lease loss cancels the current iteration; a later normal tick must reacquire ownership before resuming saved tasks and retry dates. Explicit shutdown remains permanent. The retained texts come from:

- Speeches come from `/speeches` with `include-output=xml_fragment`, month by month. Fragments marked `mtec` are machine translations. Recent months are rechecked because translations arrive later. Readers preserve the XML’s `<inline name="i">` italics in place, including editorial remarks within paragraphs and between speech paragraphs. Parentheses alone do not identify editorial remarks.
- Question and answer texts prefer the DOCX distributions of saved index records. A missing, invalid or empty DOCX can use one unambiguous API-declared PDF in the same language. PDF text is extracted locally with PDF.js; scanned pages without text are not OCRed. Original languages and English come first. `CORPUS_LANGUAGES=primary` keeps only those.

Question-file discovery retains the declared issue time and byte size. A same-URL file is checked again when its issue time is newer than the retained text's last check, or a known queued/downloaded descriptor changes. Unknown legacy descriptors do not trigger a blanket re-download or advance old retrieval dates. Pending retries retain their attempts and deadlines; a future issue time can defer work further. DOCX downloads must match a supplied byte size and contain readable text before replacing retained text. A PDF size mismatch requires the exact printed parliamentary reference; the declaration, actual byte count, file hash and mismatch remain recorded separately. PDF text never replaces readable DOCX text or settles its failed owner. A failed PDF alternative keeps the DOCX failure context and its own error; the normal owner retry honors the longer observed Retry-After. A fallback runs only when that owner is due, within the same request budget; a saved PDF step resumes at the normal retry if the budget has no spare slot. Rate limits, transport failures and cancellation do not start an alternative download. Stopped-app preparation preserves existing text IDs, FTS entries and retry clocks while enabling the PDF source format. URL-retention counts do not establish edition freshness.

Search uses SQLite FTS5 with Unicode tokenisation. Latin diacritics are folded, Greek accents are not. Endpoints:

- `GET`/`POST /api/corpus/search` search retained text only. POST accepts exact `sourceIds` scopes. The `addressee` option (GET query or POST body) matches the saved parent question’s explicit recipient before grouping or paging, including when only its answer text matches. It requires a serving activity-index generation and saved parent-question metadata for otherwise matching texts. Missing parent records make the filtered selection unavailable; they do not enter the “Addressee unavailable” bucket, which describes saved questions without supplied recipients. Search never downloads metadata. Omission or POST `null` leaves the scope unchanged; an empty string is invalid. Results are grouped by document by default. With `group=question`, a question and its linked answers count as one group. `total`, `offset` and `nextOffset` count groups. Clients must follow `nextOffset`, because `responseLimited` pages can be shorter than `limit`. Pagination stops at offset 1,000 (`truncated: true` means more matches exist; narrow the filters). Queries run one at a time in read-only workers, and busy or slow queries return HTTP 503.
- `GET /api/corpus/text?source-id=…&source-key=…` returns one stored variant with provenance, optionally highlighted with `q`.
- `GET /api/speech-transcript/{id}?lang=…` reads the exact retained speech language and its compressed XML, with source key, translation type and retrieval provenance. The corpus writer also retains the full official metadata once per speech, without duplicating XML, and derives speaker/header and intervention projections from supplied or retained fragments. Header projections include translations excluded by the text retention policy; metadata-only refreshes retain known speaker-name variants for exact current participants. Readers use that metadata and cached person records without upstream calls. Metadata retrieval and header/text provenance remain separate. Speech readers offer an inline original/translation switch when translated XML explicitly identifies one source language. Missing or conflicting source-language annotations remain gaps; an original request never displays a translated fallback as original. Selecting original text defaults a newly opened video to floor audio. Missing corpus languages or metadata use the existing speech-detail fallback. If that read fails or supplies no transcript, the detail reader can use an exact retained original or another retained language, preserving its language, source key and dates; the retained-only transcript route stays exact-language. Cancellation still stops the read, and the response records source-read failures separately from the readable retained transcript. Metadata delays and errors cannot block retained text. The read-only transcript workers have a separate concurrency limit from full-text searches, and page reads never create a corpus or start collection.
- `GET /api/corpus/status` reports coverage, including separate counts and bounded examples for unreadable source files and owners satisfied by alternative text. Settled owners do not count as successful tasks or block backfill readiness. Parser failures settle only after the same received-byte SHA-256 and parser version are rejected at least three times across 24 hours; changed bytes restart that evidence window. Cold count scans have a bounded 6.5-second reader budget (searches retain 5 seconds); a timeout returns HTTP 503 `corpus_status_timeout` and means coverage is unknown, not zero. Retry shortly. Counts remain live snapshot observations rather than cached totals. `authoritativeComplete` is always false, because upstream gaps and later publications rule out a completeness claim.

Older corpora gain metadata through the existing leased writer: a resumable, metadata-only monthly catalogue backfill, including missing-record recovery, uses the same request, retry, time and disk budgets and does not redownload transcript XML. A versioned local task refreshes unresolved contribution classifications from retained XML and verified public-source annotations, without source requests or changed retrieval timestamps; status exposes pending refreshes and failures. New and refreshed speech pages retain metadata during normal ingestion. Compact header projections preserve classification evidence even when a fragment has no paragraph text. Individual metadata failures become separate retry tasks, so text ingestion and monthly cursors can continue; status keeps those gaps visible. Known source languages remain available in the picker independently of which variants the corpus retains; selecting a variant absent from the corpus uses the detail fallback. Metadata-only refreshes preserve that known availability. `/api/corpus/status` reports retained metadata and whether that backfill is pending; source gaps remain explicit.

Speech clouds and contribution statistics prefer bounded pages from the retained speech corpus. Their totals describe saved records; a finished backfill does not establish an authoritative catalogue. The contribution card labels the latest saved speech record across the collection and warns about known missing records or unclassified contributions, rather than treating retained data alone as a gap. The existing writer builds a small local selection index from saved metadata without source requests. Clouds use exact-language paragraph text without decompressing XML, preserving translation and retrieval provenance. A single-language original stored under `mul` is recognized by its XML language. Empty or unreadable originals do not displace a readable translation for text display; header-only metadata retains its original selection rules. Omitted transcripts are counted separately; known other languages with readable, bounded paragraph text have per-language counts and selection buttons, without mixing those words into the selected language. XML fragments share the retained reader’s 2 MiB bound. Public and retained clouds both budget 4 MiB of cleaned analysis text per held sitting, with the existing week scaling; temporary timing markup does not spend that retained-text budget. Upstream response, request-time and page limits still apply. Counts describe the loaded selection and do not establish that a missing translation exists upstream. An absent corpus, unfinished local projection, empty stored selection, or known source language excluded by text retention uses the existing public-source cloud pagination. A selection never mixes local and upstream offsets. Changes to matching retained records restart the page walk; metadata and its selection fields update atomically. Saved word analysis also uses corpus paragraphs first, retaining its saved-file fallback without downloads.

Exact-ID speech context, media lookup, legacy speech readers and legislation associations reuse retained metadata where available. Context uses the saved intervention projection rather than reclassifying metadata with its XML removed. Whole-sitting context still uses the broader source feed: the corpus does not retain all procedural markers. Legislation records already in the activity index are read there first when the saved fields support the requested relationships; incomplete procedure projections retain the source fallback. Document readers retain their existing structured DOCX cache because corpus paragraph text cannot replace notes and links; official source readers continue to distinguish source records from derived projections.
